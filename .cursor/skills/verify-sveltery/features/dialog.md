# Dialog

A modal or non-modal dialog. Upstream: `packages/react/src/dialog` at Base UI v1.8.0. Local: `src/lib/dialog/`.

## Sub-features

- `Dialog.Root` renders no element. `open` and `triggerId` use the shared controllable-value helper. Omit `open` and pass `defaultOpen` to let the dialog own it. Pass `open` to hold it. `defaultTriggerId` selects the trigger for `defaultOpen`. `bind:triggerId` follows the trigger that opened the dialog.
- `onOpenChange(open, eventDetails)` runs before the change. Reasons: `trigger-press`, `outside-press`, `escape-key`, `close-press`, `focus-out`, `imperative-action`, `none`. `eventDetails.cancel()` vetoes it. `eventDetails.preventUnmountOnClose()` keeps the popup mounted after a close; `bind:this` and `root.unmount()` remove it.
- `onOpenChangeComplete(open)` runs when the open or close transition finishes. The callback is untracked, so it can write `$state`.
- `Dialog.Root` exports `close()` and `unmount()` through `bind:this`. `Dialog.createHandle()` returns a handle for detached triggers, `open(triggerId)`, `openWithPayload(payload)`, `setPayload`, `close()`, and `isOpen`. `setPayload` writes the payload onto a registered trigger and ignores an unknown id. `open` with an unknown id warns as `Dialog.Handle` and does not throw. The handle extends the shared `PopupHandle`.
- `modal` defaults to `true`: focus is trapped, page scroll locks, and an internal backdrop covers the page. `false` does none of those. `'trap-focus'` traps focus without the scroll lock or the internal backdrop.
- `disablePointerDismissal` ignores outside presses. Non-modal dialogs also stay open when focus leaves.
- Trigger: `<button type="button">`, `aria-haspopup="dialog"`, `aria-expanded`, `aria-controls` while that trigger owns the open dialog and the popup element is set, including after a container that was not in the document is attached, `data-popup-open`, `data-base-ui-click-trigger`. Server HTML leaves `aria-expanded` false and omits `aria-controls`. Disabled native triggers use the `disabled` attribute and `data-disabled`. `nativeButton={false}` uses `role="button"` and `aria-disabled`. A consumer `onclick` runs first; `preventDefault()` skips the open.
- Portal mounts on `document.body` through the shared portal. `class`, `data-*` attributes, and a consumer `{@attach}` land on that div. The attachment runs after the node is in its container. `data-base-ui-portal` stays, including when the consumer passes another value or `undefined`. A `render` snippet receives `(props, state, children)` and replaces the div; spread `props` so the move attachment and `class` land on that element. `keepMounted` leaves it mounted while closed. `container` is an element or a shadow root. `undefined` uses the parent portal or `document.body`. `null` does not mount until a container is set. Switching that container from an element back to `null` while open removes the popup and returns focus to the trigger. Server HTML omits the portal host and its popup. The host appears after the client commits. A `store` prop does not replace the dialog store. `DialogPortalProps` is the exported props type. Modal dialogs render the shared internal backdrop.
- Popup: `role="dialog"`, `tabindex="-1"`, `data-base-ui-focusable`, `aria-labelledby` / `aria-describedby` from title and description, `data-open` / `data-closed`, `data-starting-style` / `data-ending-style`, `data-nested`, `data-nested-dialog-open`, and `--nested-dialogs`. Escape closes the topmost dialog. Arrow keys do not leave the dialog.
- Backdrop: `role="presentation"`. Nested dialogs skip it unless `forceRender`. A click on the backdrop or the viewport (not the popup) closes a modal. Pointer-down does not.
- Close button uses `reason: 'close-press'`. `preventDefault()` skips it. Title is an `<h2>`. Description is a `<p>`. Generated ids use `$props.id()` with a `base-ui-` prefix.
- Initial focus moves to the first tabbable control, or to the popup when opened by touch. A nested dialog or popover that is already open stays open when the parent portal mounts. That includes a child opened from an effect during that mount, and a portal whose container is a shadow root. The parent skips its initial-focus frame while an open child is registered on that first open. Reopening a `keepMounted` parent onto a child that stayed open focuses the parent's first control. `initialFocus={false}` on a child does not move focus into the child. An unset `finalFocus` is `true`, so focus returns to the trigger only while it is still inside the popup. A `focus-out` close does not return focus. Tab, Shift+Tab, and a pointer click keep the control they landed on, including when `finalFocus` is `null`, an element, or a function. That function is not called. React calls it and ignores the result. Closing a `keepMounted` parent leaves focus in a child that stayed open. An outside click on a non-modal dialog leaves focus on the clicked button, and text typed into an outside input stays there. For any other close, pass an element or a function. `false` skips the move. A function result of `null` focuses the trigger. A parent and nested dialog that open together skip the parent's first focus frame; Escape then lands on the nested `finalFocus` outside the parent, and the parent stays open.
- A non-modal dialog closes when focus leaves its popup or the trigger that opened it for an element outside its floating tree. Tab from its last control closes with `focus-out` and lands on the next control. Tab from the open trigger moves into the dialog. Shift+Tab from the first control focuses the trigger and leaves the dialog open. That holds for the default `document.body` container, for an inline container after the root, and for an inline container between the trigger and `Dialog.Portal`, including when `open` is set from another button and the trigger did not open the dialog. Shift+Tab from the trigger that opened the dialog lands on the previous control and closes. Shift+Tab from the trigger of a dialog opened through `open` lands on the previous control and leaves the dialog open, on `document.body` and when the container sits between the trigger and `Dialog.Portal`. React does the same. Focus inside a parent or child popup does not close it, including a child portaled to `document.body`, a child with `initialFocus={false}`, and the outer popup when the inner `finalFocus` moves outside. A modal dialog does not close on that focus move. Two sibling non-modal dialogs stay open when focus enters one of them. `disablePointerDismissal` keeps a non-modal dialog open when focus leaves.
- Parts throw the upstream missing-context strings.

Differences from React Base UI, all deliberate:

- No locked controlled mode. Hold the state with `eventDetails.cancel()`. `defaultOpen` and `defaultTriggerId` are the uncontrolled start.
- No `ref` and no `actionsRef`. Use `{@attach}` and `bind:this` for `close()` and `unmount()`.
- `initialFocus` / `finalFocus` accept an element or a function, not a ref object.
- `class` on a merged host may be a Svelte class array. `style` is a CSS string. The rightmost bag wins.
- Alert Dialog and Drawer are not ported. `role` stays `dialog`.
- Outside press is one dialog listener. Mouse and touch use separate modes. A backdrop is `intentional` for both. Without one, touch is `sloppy` and mouse is `sloppy` only for `trap-focus`. `useDismiss` already tracks `pressStartedInside`. The dialog listener remains because that hook treats the portal host as inside, so a backdrop or viewport press would not dismiss.
- `COMPOSITE_KEYS` is shared with Slider (`src/lib/internal/composite-keys.ts`). Arrow keys stay inside the dialog.
- How the dialog opened is `PopupStore.openMethod`, written by `useClick`. Final focus uses the shared `returnFocus` callback, which receives how the popup closed. A `null` result focuses the trigger.
- Generated ids use `$props.id()` with a `base-ui-` prefix.
- The dev and production missing-context errors are the descriptive strings.
- A pointer click on a nested close can dismiss a non-modal parent. The dialog outside-press listener does not treat a nested popup as inside, so the click is outside the parent after the child closes. React's dismiss handler treats that nested popup as inside. Escape still closes only the child.

## How to get to it (user POV)

A consumer imports `Dialog` from `@sveltery/base` or `@sveltery/base/dialog` and renders `Dialog.Root`, `Dialog.Trigger`, `Dialog.Portal`, and `Dialog.Popup`. For verification, open `/fixtures/dialog?case=<case>`, where `<case>` is one of `standalone`, `outside`, `cancel`, `disabled`, `nested`, `nested-open`, `nested-onto`, `nested-popover`, `focus`, `nested-body`, `final-focus`, `child-initial`, `siblings`, `kept-child`, `final-outside`, `together-outside`, `tab`, `tab-inline`, `tab-ext`, `tab-between`, `tab-between-ext`, or `tab-portal-first` (`src/routes/fixtures/dialog/cases.ts`). Add `&reference` to get React Base UI with the same cases.
