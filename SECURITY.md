# Security reporting

This project is experimental and has no supported production release or promised response time. Report non-sensitive bugs through [issues](https://github.com/sveltery/base/issues).

For a suspected vulnerability, avoid publishing exploit details, credentials or private data in a public issue. If GitHub offers **Report a vulnerability** on the repository's Security tab, use that private reporting flow. Its availability depends on repository settings and is not guaranteed by this document. Otherwise open a public issue containing only a request for a private contact channel, then share details after a maintainer establishes that channel. There is no dedicated security email address at present.

Include the affected commit or version, minimal reproduction, impact and any proposed fix. Never include live secrets or third-party personal data. Preserve upstream attribution and report upstream-specific vulnerabilities to the upstream project's own security channel.
