# UseRender composition

`UseRender` is a native Svelte 5 component adaptation of Base UI 1.8.0's public `useRender` hook, at immutable commit `47b40521eab921c2756bf9bdb0b0f07fbfdb8c8c`. It renders an intrinsic element or replacement snippet. Import it from `@sveltery/base` or `@sveltery/base/use-render`. This is a [delegated PM design decision](https://github.com/sveltery/base/pull/40#pullrequestreview-5396533264); explicit user acceptance of this additional component/name/return substitution is not recorded. The seven upstream ReactElement/null return assertions remain divergent and unported, with zero unchanged type credit.

The public parameters are `defaultTagName` (default `div`), `enabled` (default true), `state`, `stateAttributesMapping`, ordinary-object `props`, replacement `render`, separate `ref` and optional `bind:element`, and `children`. HTML and SVG hosts are supported. State values become lowercase `data-*` names: true produces an empty attribute, false and other falsy values disappear, and truthy values stringify. A custom map replaces that property's default mapping, even when it returns null. Explicit props override state attributes.

Replacement snippets receive merged symbol-bearing props, the current state and children. They must spread the supplied props onto their actual host so consumer and component attachments reach that element. To compose replacement-owned props last, use `mergeProps(suppliedProps, ownedProps)`; the first input retains enumerable attachment symbols. String CSS can be composed with `${suppliedProps.style ?? ''};font-size:16px`. References remain separate from prop merging. A replacement-owned ref uses its own attachment. Native `preventDefault()` does not suppress Base UI handlers; `preventBaseUIHandler()` does.

The private closure alone accepts ordered objects/getters and state-dependent class/style callbacks. Getters receive the accumulated props and replace them; they own callback chaining. These internal options are not added to the public hook's ordinary `props` object contract. Existing components and the old private Dialog Element are unchanged.

`ref` accepts callback/object refs or an array of them. Callback cleanup functions run on detach; callbacks without cleanup receive null. Object refs publish the actual host and clear on detach. Individual ref identities control attachment memoization. A replaced ref cleans up before host attributes change, and its successor attaches after the update; class-only updates retain the existing refs. `bind:element` starts undefined unless initialized by its owner, publishes the host after attachment, and becomes null after removal, following the existing A-01 lifecycle. SVG, replacement-host swaps, ref-shape changes and teardown use the same ownership boundary.

On full owner unmount or snippet-controlled host replacement, native attachment cleanup receives an already detached host; React cleanup runs while connected. This additional teardown observation follows a separate [delegated PM lifecycle decision](https://github.com/sveltery/base/pull/40#pullrequestreview-5397289277), with explicit user acceptance unrecorded and zero unchanged credit for the divergence; see the [compatibility record](../parity/use-render/compatibility.md). Ref replacement, disabling, default-tag changes, outer default-host/snippet branch changes and changes of supplied snippet identity clean up before host removal or mutation.

A changed supplied snippet identity replaces its native host, even when the next snippet renders the same intrinsic tag; React can reuse that type/key host and retain its refs. This observable identity/ref difference follows the [specific PM clarification](https://github.com/sveltery/base/pull/40#pullrequestreview-5397832880), with explicit user acceptance unrecorded and zero unchanged credit. Keep the snippet identity stable and update its reactive props/state arguments to retain the native host and supplied refs. The after-removal cleanup boundary above applies only to host changes controlled inside an unchanged snippet or full owner unmount.

When `enabled` is false, no state mapping, getter, class/style callback, replacement snippet or new ref work runs; an existing host still tears down. Only a default intrinsic button receives `type="button"`, and only a default intrinsic image receives `alt=""`; explicitly supplied props override defaults. Replacement snippets own their defaults.

The [dedicated assertion record](../parity/use-render/README.md) separates public declarations, internal closure declarations, return types, and supplements. React lazy/Suspense, Flight/RSC wrappers and React diagnostics are unimplemented; no Svelte equivalents or parity credit are invented. Proposed [PR #40](https://github.com/sveltery/base/pull/40) anchors the delegated PM public design review. Public root and `@sveltery/base/use-render` expose the component and nine named native type aliases. Installed tarball checks verify entry identity, private export exclusion, SSR, DOM refs/updates/cleanup, types and MIT notices; they add no ordinary assertion credit. No package publication or production-readiness claim is made.
