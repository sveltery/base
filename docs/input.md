# Standalone Input

`Input` is exported from `@sveltery/base` and `@sveltery/base/input`. It renders a native input, accepts native props and supports controlled `value`, uncontrolled `defaultValue`, explicit or SSR-stable generated IDs, state-dependent class/style, replacement snippets, attachments and `bind:ref`.

```svelte
<script lang="ts">
  import { Input } from '@sveltery/base';
  let value = $state('');
</script>

<Input {value} onValueChange={next => value = next} name="title" required />
```

Each text input edit calls `onValueChange(value, details)` with reason `none` and the native input event. Checkbox/radio activation uses the native click event, as in the pin. Consumer and render-owned handlers follow the existing merge/prevention contract; native onclick composes checkable value requests and oninput composes text requests. Controlled owners accept, reject or rewrite the requested value; the actual DOM value settles after the owner update. Uncontrolled edits stay native, including when `details.cancel()` is called. Cancellation does not undo a native edit or call preventDefault.

Native checkbox/radio inputs also accept `checked` and `defaultChecked`. Controlled checked edits restore live owner props synchronously after the composed click callback, without flushing unrelated Svelte state; a radio selection restores controlled siblings in the same final native root, name and form. Uncontrolled siblings retain native selection. Controlled checked uses its initial checked state as the reset default and ignores a conflicting defaultChecked, matching the pin; later checked updates keep that default. A replacement host starts its own default from the current owner. Uncontrolled defaultChecked updates change the next reset without changing current checked state. Reset emits no onValueChange request, and cancellation retains current checked. I-02's native value/defaultValue choice does not apply to checked defaults.

Checked property tracking follows actual React: programmatic checked assignments update the tracker, while native activation and reset bypass its setter. A selected radio does not emit a duplicate value request. A reset can therefore leave a tracker value that suppresses the next checkable request; this source behavior is preserved.

The [checked compatibility record](../parity/input/checked/compatibility.md) keeps callback, canceled native activation and timing evidence separate from value timing, including distinct jsdom and Chromium rollback observations. Direct Kit checkbox descriptor ownership and stopped replacement click completion remain blocked prerequisites at the first secured repair checkpoint. I-03's accepted value timing does not approve checked delays or lost callbacks. Passing characterization is not parity credit.

Controlled restoration follows Svelte’s tick after dispatch: rejected/prevented edits remain visible immediately after native event dispatch and settle to the owner value after tick; rewritten edits settle to the rewritten value. React restores these before dispatch returns. The user accepted native Svelte restoration timing on 2026-10-02, recorded as I-03 in [the compatibility register](upstream-differences.md). The programmatic dispatch matrix records earlier target/form reads of the edit in both frameworks, then Svelte edit reads through later root/document listeners until tick. If a browser tick runs while an input event is still dispatching, Input defers its manual restoration to a task so native form listeners and delegated owner callbacks receive the edit first. Pending work belongs to the actual host and is canceled on replacement or removal; a successful native reset during the edit keeps its reset default. Input passively observes its own input events in capture on the nearest native ancestor, before target attachment listeners can reset the form. Temporary listeners on the host’s native tree root observe reset dispatch. An attachment-scoped Svelte effect follows reactive form association changes while reset handlers run, and a late bubble observer snapshots ordinary handler changes. Completed reset records stay fixed when a later callback changes the form. The paired native regressions cover reassociation into and out of the resetting form, cancellation and stopped propagation. Canceled and unrelated form resets still allow controlled restoration; reset observation is removed when pending work settles; all listeners and timers are removed with the host. Trusted phase regressions retain the actual Kit listener and native comparator.

Standalone state is exactly `{ disabled, touched: false, dirty: false, filled: false, focused: false, valid: null }`. Typing, focus, blur and native validity do not invent Field state or data-invalid. Native required/type/pattern validation and explicitly supplied ARIA attributes remain available. Field registration, touched/dirty/filled/focus state, contextual validation including asynchronous validation, Field label/message relationships and Form integration are deferred; there are no placeholder Field/Form exports.

One reset combination is unsupported: while a controlled edit is awaiting restoration, a reset handler imperatively moves the input into or out of the resetting form and stops reset propagation. For example, calling `input.setAttribute('form', ...)` inside `onreset` together with `stopPropagation()` or `stopImmediatePropagation()` hides the final association from Input's observers. Moving out can leave a rejected edit in the DOM; moving in can overwrite the native reset default with the owner value. Use reactive Svelte `form` props for reassociation in a stopped handler, or allow reset propagation for imperative reassociation. Ordinary resets, cancellation, attachment-triggered reset, completed-reset-then-reassociation and the tested reactive reassociation paths remain supported. The user accepted this specific limitation on 2026-10-02; [I-04](upstream-differences.md#i-04-accepted-stopped-imperative-reset-reassociation-limit) records the decision and [retained reproductions](../parity/input/reset-limit/README.md). This does not broaden I-03's accepted next-tick timing difference.

`value` and `defaultValue` retain native Svelte meanings. For a controlled `value="owner"` alone, the reset default is empty; with `defaultValue="seed"`, native reset uses seed. Reset leaves the owner’s controlled value unchanged and emits no onValueChange request. Canceling the native reset keeps the current DOM value. React’s pinned standalone Input instead uses the controlled value as its reset default. This is the user-directed intentional native reset difference, recorded as I-02 in [the compatibility register](upstream-differences.md). Next owner changes and controlled input edits synchronize the value again.

Fixtures demonstrate direct SvelteKit 2.70.3 remote field spreads: `<Input {...form.fields.name.as('text')} />`. Kit supplies both the current value and initial default through reactive getters and receives native bubbling events. Kit’s own reset handler awaits a tick and clears issues/touched, including a canceled reset event. In secured Chromium, trusted reset-button activation leaves the remote owner at its previous value while the DOM resets to its native default; successful remote-submit reset runs inside script and resets both. The native comparator records the same Kit behavior. No Kit imports enter the runtime package. Native reset and successful remote-submit reset are covered separately in [the feature evidence](../parity/input/README.md).
