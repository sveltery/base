# Standalone Input

`Input` is exported from `@sveltery/base` and `@sveltery/base/input`. It renders a native input, accepts native props and supports controlled `value`, uncontrolled `defaultValue`, explicit or SSR-stable generated IDs, state-dependent class/style, replacement snippets, attachments and `bind:ref`.

```svelte
<script lang="ts">
  import { Input } from '@sveltery/base';
  let value = $state('');
</script>

<Input {value} onValueChange={next => value = next} name="title" required />
```

Each native input edit calls `onValueChange(value, details)` with reason `none` and the native event. Consumer and render-owned handlers follow the existing merge/prevention contract. Controlled owners accept, reject or rewrite the requested value; the actual DOM value settles after the owner update. Uncontrolled edits stay native, including when `details.cancel()` is called. Cancellation does not undo a native edit or call preventDefault.

Controlled restoration follows Svelte’s tick after dispatch: rejected/prevented edits remain visible immediately after native event dispatch and settle to the owner value after tick; rewritten edits settle to the rewritten value. React restores these before dispatch returns. The user accepted native Svelte restoration timing on 2026-10-02, recorded as I-03 in [the compatibility register](upstream-differences.md). The programmatic dispatch matrix records earlier target/form reads of the edit in both frameworks, then Svelte edit reads through later root/document listeners until tick. If a browser tick runs while an input event is still dispatching, Input defers its manual restoration to a task so native form listeners and delegated owner callbacks receive the edit first. Pending work belongs to the actual host and is canceled on replacement or removal; a successful native reset during the edit keeps its reset default. A temporary capture listener on the host’s native tree root observes resets of its current associated form, including reactive form reassociation and form handlers that stop bubbling. Canceled and unrelated form resets still allow controlled restoration; the observation is removed when pending work settles or the host is removed. Trusted phase regressions retain the actual Kit listener and native comparator.

Standalone state is exactly `{ disabled, touched: false, dirty: false, filled: false, focused: false, valid: null }`. Typing, focus, blur and native validity do not invent Field state or data-invalid. Native required/type/pattern validation and explicitly supplied ARIA attributes remain available. Field registration, touched/dirty/filled/focus state, contextual validation including asynchronous validation, Field label/message relationships and Form integration are deferred; there are no placeholder Field/Form exports.

`value` and `defaultValue` retain native Svelte meanings. For a controlled `value="owner"` alone, the reset default is empty; with `defaultValue="seed"`, native reset uses seed. Reset leaves the owner’s controlled value unchanged and emits no onValueChange request. Canceling the native reset keeps the current DOM value. React’s pinned standalone Input instead uses the controlled value as its reset default. This is the user-directed intentional native reset difference, recorded as I-02 in [the compatibility register](upstream-differences.md). Next owner changes and controlled input edits synchronize the value again.

Fixtures demonstrate direct SvelteKit 2.70.3 remote field spreads: `<Input {...form.fields.name.as('text')} />`. Kit supplies both the current value and initial default through reactive getters and receives native bubbling events. Kit’s own reset handler awaits a tick and clears issues/touched, including a canceled reset event. In secured Chromium, trusted reset-button activation leaves the remote owner at its previous value while the DOM resets to its native default; successful remote-submit reset runs inside script and resets both. The native comparator records the same Kit behavior. No Kit imports enter the runtime package. Native reset and successful remote-submit reset are covered separately in [the feature evidence](../parity/input/README.md).
