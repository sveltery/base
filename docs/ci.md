# Continuous integration

`.github/workflows/ci.yml` runs on every pull request, pushes to `main`, and manual dispatch. Pull request jobs check out the exact head SHA, so the workflow run's `head_sha` can be compared with the final reviewed commit. Stable check names are `Standards` and `Verification`.

`Standards` installs the workspace with its frozen lockfile, then runs the shared root ESLint and Svelte-aware Prettier commands plus commit whitespace checks. `Verification` installs the same frozen workspace and runs script regressions, one native library pack, TypeScript/Svelte diagnostics, runtime tests, the fixture SSR/client build, packaged runtime boundary checks, and the isolated tarball consumer/license check. It does not publish a package.

The library follows the official `sv create` scaffold conventions inside `packages/base`, with a development-only Kit 3 preview and Vite configuration. Kit and React remain excluded from library runtime imports. Vitest projects preserve the existing Node `server` and jsdom `dom` collections; the `client` project tests a real public Button in secured Chromium. Only that new project requires Vitest-counted assertions, so existing Node assertion helpers retain their original behavior. The `Dialog browser` job runs `pnpm test:component` after its official Chromium setup, then preserves the established paired Source Playwright selections. Both runners use one worker and zero retries.

The producer and standards toolchains use TypeScript 6.0.3; library packaging uses `@sveltejs/package` 3.0.0. The tarball step validates all packaged export targets, preserved `.svelte`/rune `.svelte.js` modules and declarations, attribution and excluded test/cache files. publint 0.3.25 (`--strict`) and AreTheTypesWrong core 0.18.5 read that same tarball without repacking. ATTW's public resolution filter requires Bundler resolution for every public entry and Node16 ESM for the plain-JavaScript `merge-props` entry, without excluding rules or entries. Its complete analysis is retained at `.checks/npm-package/sveltery-base-0.0.0.attw.json`; the CLI `esm-only` profile reports unresolved official `.svelte` declarations under Node16 ESM. Component entries require Svelte-aware Bundler tooling; Node16 component, legacy Node10 and CommonJS resolution are unsupported. Real installed Svelte consumers remain required because those metadata tools do not compile components or establish runtime compatibility. The existing isolated remote-contract consumer retains TypeScript 5.9.3 as minimum-compiler coverage. See [release preparation](releasing.md) for the fresh-build `pnpm package:check` command and the separate future publication steps.

Verification creates the production workspace package closure once and reuses its recorded archives across consumer checks. Verification retains the exact tarballs and unmodified ATTW analysis as the `npm-package-analysis` artifact for 14 days, including when a later consumer check fails. Artifact retention does not turn unsupported-mode problems into a passing compatibility claim.

Standards and Verification use Ubuntu 24.04; Dialog browser, Collapsible browser, Meter browser, Avatar browser, Accordion browser DirectionProvider browser and Native snippets browser use Ubuntu 22.04 (an officially supported Playwright/GitHub runner image). Jobs use Node 24.x and pnpm 12.6.0. GitHub Actions are pinned to full commit SHAs; version comments identify the reviewed releases. Update pins in a reviewed PR. All jobs have `contents: read` permissions and cancellation of older runs for the same PR/ref. Standards, Verification and focused browser jobs have a 15-minute timeout; the combined Dialog browser job has 60 minutes for the expanded suite plus artifact collection and cleanup. Checkout does not persist credentials. There are no secrets, deployments, writable tokens or `pull_request_target` code execution.

## Proposed main-branch protection

Apply only after both checks have passed on the reviewed PR head and the maintainer has approved the exact settings at action time:

- Require a pull request and resolve review conversations.
- Require `Standards` and `Verification`, with branches up to date before merge.
- Block force pushes and branch deletion.
- Apply the rules to administrators; keep normal reviewed PR merges available.
- Require zero GitHub human approvals while a single maintainer operates the repo; independent source review remains part of the documented merge procedure.
- Do not add bypass actors, new grants, secrets, deployment settings or signing requirements through this change.

This document proposes settings; it does not assert they are active. The available connector exposes no repository-administration write action. Adding browser checks to protection needs a new explicit proposal after the real job has passed.

The Utils package uses the same workspace lifecycle. Bootstrap produces genuine native package outputs in dependency order after its frozen install. Cold root checks and tests prepare those outputs, then run every library package's server, DOM or Chromium project. Combined verification prepares one archive per package and reuses the resulting outputs and exact dependency archives. Root `dev` and `check:watch` use pnpm's parallel script runner to keep package output current alongside normal preview, app or check watchers; package source aliases are not used. The actual installed Utils export graph is classified from emitted JavaScript AST, then every plain ESM entry is imported without a compiler and every rune-dependent entry is imported through the isolated peer Svelte compiler. This execution check complements all-export Bundler and Node16 ESM declaration resolution; it does not promise ordinary Node execution of rune APIs.
