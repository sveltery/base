# Scoped Svelte modernization

This fixture and tooling change starts from Base main `cdd1c4f3bef7d329b890de42c05aeb9d4402e656`. It preserves the existing Toast fixture's observable rendering and component state lifetimes. It adds no runtime API substitution, intentional Base UI behavior difference or upstream parity credit. The behavior reference remains Base UI v1.8.0 at `47b40521eab921c2756bf9bdb0b0f07fbfdb8c8c` and the [compatibility register](upstream-differences.md) retains its existing decisions and incomplete scope.

## Changes and version support

In [ToastContents.svelte](../apps/fixtures/src/lib/ToastContents.svelte), the two identical Description/Action guards now share a top-level `{const showDetailParts = $derived(...)}`. The expression retains all three conditions: no limited scenario, no `close`, and no `close-all`. `$derived` makes prop changes update the guard. Existing state, context and callbacks retain their script initialization and component lifetime; moving state into conditional markup would change that lifetime.

[Declaration tags](https://svelte.dev/docs/svelte/declaration-tags) are stable since Svelte 5.56.0. The workspace and isolated standards installation both pin Svelte 5.57.1, and the library peer range is `^5.57.1`. No package versions or lockfiles change.

The fixture's existing adapter-auto configuration moves from the deleted `svelte.config.js` into `sveltekit({ adapter: adapter() })` in [vite.config.ts](../apps/fixtures/vite.config.ts). [SvelteKit's official plugin documentation](https://svelte.dev/docs/kit/@sveltejs-kit-vite) records support since 2.62; installed Kit 2.70.3 also documents this in its declarations and resolves configuration through the Vite setup plugin. The adapter remains `@sveltejs/adapter-auto` 7.0.1. This uses the installed Kit 2 API without upgrading to Kit 3.

[ESLint](../.github/standards/eslint.config.mjs) enables `svelte/no-at-const-tags` as an error. The [official rule documentation](https://sveltejs.github.io/eslint-plugin-svelte/rules/no-at-const-tags/) records introduction in plugin 3.20.0; the isolated installation is already pinned at 3.23.0. The rule targets legacy `{@const ...}` in runes mode on supported Svelte versions. The [standards entrypoint](../.github/standards/check.sh) uses one quoted `apps/fixtures/*.{js,ts}` glob to retain both configuration extensions after the only JavaScript config is removed. Keeping its old `apps/fixtures/*.js` argument makes ESLint fail because no files match.
