# Canonical Composite state owners

The canonical Composite prerequisite converts four reusable state and resource owners into classes in their existing modules: `useCompositeRoot`, `createCompositeList`, `useCompositeListItem` and `useCompositeItem`. Existing internal names remain recognizable; callers construct each owner with `new`. This changes private representation, not public component props or business policy.

The [complete pinned and native closure](../parity/composite-owners/README.md) starts from MIT Base UI 1.8.0 `47b40521eab921c2756bf9bdb0b0f07fbfdb8c8c`. Root retains highlighted state, active/replacement fallback, caret-aware navigation, loop/grid branches and deferred focus. List retains its single registration map, reserved and automatic indexes, label fallback, listener-before-consumer publication, reorder observer and cleanup. ListItem retains guessed/internal indexes, live metadata registration and subscription cleanup. Item composes that same registration owner and publishes its actual host with native attachments.

Stable services passed through contexts or attachments are bound arrow fields. Native runes, direct effects, context, attachment tracking and independent cleanup remain authoritative. Stateless fallback/modifier selectors, snapshot/ordering/ancestor/move functions, grid navigation and context readers stay functions. No React callback-ref fanout, render/commit engine, state snapshots or CSS custody is introduced.

Actual callers include Radio/RadioGroup, Toggle/ToggleGroup, Toolbar, Menubar and Menu item/Positioner/submenu composition. The canonical conversion does not edit Button, TransitionStatus, Field validation, nativeProps or navigation/composite utility bodies. PR #42 exclusively owns the two computed-style fidelity repairs; PR #73 owns native empty CSS-string transport. Final acceptance requires normal integration after reached prerequisites are accepted into main, then fresh entire-closure review and exact-head gates. Accordion's private automatic-index implementation and separate Floating owners remain outside this prerequisite's acceptance.

Historical assertion/source records and failed receipts remain unchanged. Existing tests and new packed/SSR/hydration/browser supplements have separate provenance; this representation change grants zero new unchanged upstream assertion credit. Native attachment timing and element/style defaults retain the recorded native behavior. Independent source/native/maintainability review, full hosted Standards/Verification, secured browser and strict packed declarations are required before lead acceptance. This prerequisite does not claim complete feature or library parity.
