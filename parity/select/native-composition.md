## Explicit remote-form composition proposal

Current accepted `RemoteControl` routes bare `select`/`select multiple` through real `RemoteNativeControl`; that remains native `<select>` behavior. The existing authored checked-family route is the model for a separately leased authored Select route: before native-select registration, delegate an explicitly authored Select render snippet to a small `RemoteSelectControl` boundary. That boundary spreads semantic Select props, publishes the canonical native serialization-name override and actual Trigger ref, and lets the real Select Root/Trigger/hidden inputs own registration, dirty/filled/touched/validation and cancellation. It must not instantiate RemoteNativeControl or Field.Control behind the authored Select, store a second selection, infer prefix names or register a second reset listener.

The installed explicit SDK opt-in is Kit2.70.3, release pin `39e8e1fbd4feba7f22dd46bfdf7335362c38de16`, with the existing approved cancellation/reset patch. A read-only source seam inspection of actual `form-utils.js:create_field_proxy` and client form attachment confirms: `as('select')`/`as('select multiple')` return a live value and the exact native name (including `[]`); the public accessor has `.set(value)`; Form listens to actual input/name serialization, and the patched reset waits for native defaults before updating the owner. This is a bounded SDK seam inspection, not a claim to have read or accepted the SDK's complete source closure. The existing [SDK evidence](../../docs/sveltekit-submit-compat.md) remains binding.

The concrete proposed ownership table, guarded writer, scalar-null encoding, correlated Source callback/render types, wrapperless Root versus Trigger host split, and actual SDK string/string[] limits are in [remote-select-contract.md](remote-select-contract.md). Defined authored value/defaultValue select manual Source ownership and do not call the adapter writer. Remote mode rereads the live owner/current descriptor fallback on every evaluation and normalizes absence only at the adapter boundary. This replaces the earlier ambiguous “seed once, then live owner” promise; no cached initial fallback, extra selection store or reset listener is proposed.

The public type proposal explicitly records that Svelte runtime context does not infer a child Control generic from ancestor Root name/as. The existing checked-family callback shape is insufficient for Select. A source-correlated render union, genuine route overloads and actual installed positive/negative consumers remain separately reviewed scope; no unknown cast or unverified overload supplies acceptance. Missing `.set`, malformed values and obsolete accessor requests have explicit proposed behavior rather than silent guessed mutation.

This extension remains blocked pending separate Root design approval and a scoped RemoteControl/new adapter/structural-writer/public-type lease. Root name/as inference must continue to derive from real SDK accessor arguments. Actual Kit string/string[] scalar/multiple/manual/programmatic/native-reset/POST/issue/ref witnesses, current native/checked/text/file regressions, and same-head Source/native/maintainability review remain required.
