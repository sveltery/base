## Explicit remote-form composition proposal

Current accepted `RemoteControl` routes bare `select`/`select multiple` through real `RemoteNativeControl`; that remains native `<select>` behavior. The existing authored checked-family route is the model for a separately leased authored Select route: before native-select registration, delegate an explicitly authored Select render snippet to a small `RemoteSelectControl` boundary. That boundary spreads semantic Select props, publishes the canonical native serialization-name override and actual Trigger ref, and lets the real Select Root/Trigger/hidden inputs own registration, dirty/filled/touched/validation and cancellation. It must not instantiate RemoteNativeControl or Field.Control behind the authored Select, store a second selection, infer prefix names or register a second reset listener.

The installed explicit SDK opt-in is Kit2.70.3, release pin `39e8e1fbd4feba7f22dd46bfdf7335362c38de16`, with the existing approved cancellation/reset patch. A read-only source seam inspection of actual `form-utils.js:create_field_proxy` and client form attachment confirms: `as('select')`/`as('select multiple')` return a live value and the exact native name (including `[]`); the public accessor has `.set(value)`; Form listens to actual input/name serialization, and the patched reset waits for native defaults before updating the owner. This is a bounded SDK seam inspection, not a claim to have read or accepted the SDK's complete source closure. The existing [SDK evidence](../../docs/sveltekit-submit-compat.md) remains binding.

The proposed boundary reads the actual accessor/descriptor each time, with authored values/names/IDs/errors/options/callbacks retaining explicit precedence. For remote-owned values, seed Source-compatible null or empty multiple selection from first mount when the owner is undefined, then use the actual live owner. Its value-change callback first calls the consumer with the Source details; only an accepted request delegates to the exact public accessor `.set(nextValue)`. That public owner operation must use the actual accessor object and method receiver, not guessed path mutation. Manual non-remote controls keep normal Source controlled/uncontrolled ownership. Direct descriptor spreads and their attachments remain native, and normal form serialization comes from Source's real scalar/multiple inputs using the descriptor's exact name. No synthetic input replay is proposed for setting remote selection.

This extension needs a scoped `RemoteControl`/new adapter/structural-accessor/public-render-type lease, separately identified positive/negative typed consumers, and actual Kit scalar/multiple/manual/programmatic/native-reset witnesses. Source SelectRoot's generic API and current native/checked/text/file routes must retain their contracts. Original Select assertions earn no credit from this SDK extension. Invalid/canceled zero-POST followed by valid positive-POST, issues/logical-name versus native-name, descriptor attachment/ref lifetime and settled native reset remain required acceptance gates. Nothing here publishes or applies another Kit patch.

## SSR, defaults, public contracts and final review

Source Root is wrapperless, has empty State and children only. Scalar default is null; multiple default is the source frozen empty array; defaultOpen=false, modal=true, readOnly=false, highlightItemOnHover=true, disabled includes optional Field state. Preserve two independent controlled modes and the source conditional `Multiple extends true ? Value[] : Value`, including null/undefined value/defaultValue and the callback's different null rule. Part defaults, id omissions, ref order, finalFocus and no Portal keepMounted/Popup initialFocus remain in the component plan and exact public type gates.

Initial state/IDs/labels/serialized native inputs must render on the server with no effect/document access. Hydrate those actual same DOM nodes and preserve native attributes/properties, attachment ownership, generated IDs and portal omission/mount behavior. Literal React/Svelte input/reset/label/style/default observations retain actual Svelte defaults where inherent; divergent observations keep Original provenance and receive zero unchanged credit. Do not introduce a React commit kernel, event replay, ref emulation or controlled-restoration layer to remove those differences.

Root approval must cover this complete Source/native composition, component lifetimes, value/label/control/validation/forms/defaults/ref/render/SSR/hydration/public generic and negative type proposal and [behavioral test plan](manual-test-plan.md). Pending helpers must integrate through their owner; the four missing helpers and remote extension need scoped leases. Final SourceFull review must inspect the actual implementation and inherited helpers at the exact accepted head, with maintainability/native review and actual focused/SSR/hydration/secured browser/CI/installed-consumer evidence. This documentation establishes none of those future acceptance gates.
