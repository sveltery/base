## Native ownership proposal

Root creates one SelectStore and one unsynced FloatingRootStore with initial controlled/default values before rendering descendants, including SSR. Derived value/open/disabled/name reads remain native live getters. Stable command closures read current props and current canonical stores directly. Notifications retain their synchronous business order; effects synchronize DOM-dependent registration after the actual host exists and do not replace initial SSR state.

Root requests value with one cancelable details object, then Item requests close with a separate details object in single mode. Cancellation can reject selection while accepting close. FloatingRootStore emits openchange before Root's consumer callback on the syncOnly=false path; Popup's syncOnly=true command has another source sequence. Controlled owner updates rerun the source dirty/filled/validation and selection-index business, while temporary active/selected indices remain navigation/layout state rather than another value owner.

Source business publications target the actual host via native bindings, bindable refs and independent attachments. React callback-ref identity/fanout is deliberately absent; retain required business publication order within the part’s actual owner. Every observer/listener/timeout/frame/animation completion belongs to the source component/session that installs it. Cleanup checks installed identity before releasing context fields/host publications, aborts obsolete completions and rejects asynchronous geometry writes after replacement. Root, Positioner, Popup, List, ItemText, Value, arrows, Portal and hidden input have distinct source lifetimes and must retain them.

Hidden native input markup uses source value/required/name/form/autocomplete/readOnly/disabled rules and the existing `useFieldControlNativeName` serialization override. Logical Field/Form registry and errors use source business names. Registration points to Trigger; validation points to the real shared input. A consumer can use Select without Field/Form, with explicit manual overrides, with external libraries or under typed remote Field context without importing SvelteKit runtime. No second selection/reset owner is introduced. The current SDK native-select adapter is evidence of this integration boundary, not implementation of the public Select family. The separately proposed [remote owner/type contract](remote-select-contract.md) defines manual value/default opt-out, current fallback/undefined/reset normalization, guarded receiver-preserving writer, scalar-null encoding and honest correlated render/public type scope; none is accepted by this reading record.

Public Root generic planning retains the exact source conditional `SelectValueType<Value, Multiple> = Multiple extends true ? Value[] : Value`. Both value and defaultValue also accept null/undefined, including multiple=true; onValueChange adds null only when Multiple does not extend true. Root State is empty and Root has children rather than a render prop: no Root render/state callback API is added. Readonly item/group arrays and comparator inference, mixed true/false/undefined multiple, objects and arrays as scalar values, exact optional properties, omitted Label/Item IDs, public namespace types and negative consumers require mapped type gates. Native authored refs/snippets/HTML hosts and typed SDK/external-library extensions receive their own positive and negative tests.
