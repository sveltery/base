# Input and Field.Control source realignment

Reference: Base UI v1.8.0 `47b40521eab921c2756bf9bdb0b0f07fbfdb8c8c`, MIT. The [machine-readable correspondence](source-correspondence.json) records immutable source hashes and direct imports; [the existing inventory](upstream-inventory.json) records the broader Field/Form/Fieldset source and assertions. This is a source checkpoint, not an execution or structural acceptance claim.

The graph is Input → Field.Control → FieldRoot/Form/Labelable contexts, controlled state, registration, value-change tracking, timeout, event details, state mapping and shared render closure. Field.Root → LabelableProvider → FieldRootInner → useFieldValidation + useFieldControlRegistration. LabelableProvider and useLabelableId share one actual LabelableContext. The default source contexts are real missing-provider behavior; provided Roots use reactive state and the original validation/registration bodies.

The prior combined `field/controller.svelte.ts` and Input-owned Field.Control body are removed. Field.Control has its own body and public types; Input forwards to it and derives its state/event types from it. `field/context.ts`, `field/labelable.svelte.ts` and `form/context.ts` are import facades for existing parts, with no alternative registration or validation runtime.

The user clarified on 2026-10-03 UTC that source composition/business logic must remain while native element behavior keeps Svelte defaults. Therefore the port retains native input/change/cancellation/reset/DOM ownership. It adds no ReactDOM property tracking, checked restoration, activation replay, source reset-default forcing or input commit scheduler. The shared renderer owns a literal native `<input>` with ordinary props and attachments. Real SvelteKit field/form descriptor objects remain directly spread; runtime imports have no React or SvelteKit dependency. Historical source/reference assertions remain comparison evidence; a differing native expectation receives zero source parity credit. Historical I-02/I-03/I-04 decisions remain recorded in their original scope.

Shared utils and useRenderElement are separate dependency PRs under development. Their closure records and exact review heads must be linked before this feature can compile or be claimed complete. The inherited `mergeProps`, event-detail/reasons/types helpers, Fieldset context and non-Control Field parts remain explicitly subject to full-closure review. Existing ordinary candidate bodies have zero final credit until rerun and reviewed on the final source-derived head. Public exports, packed notices, final browser evidence and merge are still pending.
