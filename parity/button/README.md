Svelte adaptations: public named `Button` and `@sveltery/base/button`, named `ButtonProps`/`ButtonState` type exports in place of React component namespace types, lowercase DOM event props, string CSS style, `class`/`style` functions receiving `{ disabled }`, children snippets, `render(props, state, children)` snippets, `bind:ref` and enumerable attachment symbols. Render snippets must spread the supplied merged props onto their DOM host; they can use `mergeProps(props, ownProps)` to retain render-element-first handler ordering and cancellation. These adaptations require maintainer acceptance and are not recorded as approved deviations. Native DOM events receive the upstream `preventBaseUIHandler()` channel. Calling it cancels Base UI synthesis without preventing browser defaults or bubbling; `preventDefault()` retains its separate native meaning.

The component is an independent action primitive. It has no composite context, popup state or actions handle. Native buttons with omitted type default to `type="button"`; explicit undefined/null removes the attribute exactly as upstream ordinary-prop merging does (the browser then treats the native button as submit). Explicit submit/reset and form attributes use the browser. Custom elements use `nativeButton={false}`, role/button tabindex, Enter keydown and Space keyup clicks with modifiers and native link activation. Disabled guards wrap consumer click/down/key handlers; hover, focus and blur remain available. `focusableWhenDisabled` replaces native disabled with aria-disabled, preserving focus and allowing Tab away. Upstream's non-native limitation is retained: Space keydown default prevention alone does not cancel a subsequent unprevented keyup; no derived-state copying effect or invented cross-key state is introduced.

Readiness for styled UI/CMS is gated on exact-head local verification, secured hosted Chromium execution of both reference and Svelte assertions, independent review and completed automatic review, then parent-coordinated merge. No full Button conformance or whole-library parity claim, CMS integration, release, deployment or merge is authorized by this slice.

Landed uncredited upstream correction ([PR #17](https://github.com/sveltery/base/pull/17)): disabled `mousedown` also calls preventDefault, matching the existing disabled click/pointerdown cancellation intent. At the pin, onMouseDown suppresses only the consumer callback. [Chorded mouse presses](https://www.w3.org/TR/pointerevents3/#chorded-button-interactions) can supply an additional mousedown without another pointerdown; the added trusted-input probes compare the disabled default/focus path against unchanged React reference behavior. This difference earns no parity credit and is not an approved-deviation entry. Specific deviation approval is not recorded in the cited evidence; do not claim complete 1:1 mouse fallback behavior.
