`RemoteNativeControl` is the one necessary native-host extension where source Control's string input contract cannot represent selected arrays/files/options. It has no independent controlled state, selection store, reset listener, event replay or attachment kernel. Text and numeric input use the original Control. Native option serialization and business logical names remain separate at the shared native-input-name context.

The native attachment type correction follows Svelte 5.57.1's public `elements.d.ts: HTMLAttributes<T>` symbol declaration, `Attachment<T> | false | undefined | null`. A fixed `Attachment<Element>` would reject native button/input/HTMLElement callbacks under strict contravariance, so the unknown-host slot uses Svelte's host generic directly rather than adding a projection or casting props. The Base UI reference remains the pinned open `HTMLProps` render contract and `BaseUIComponentProps` render parameter. `scripts/fixtures/remote-form-api/NativeHosts.svelte` is an actual packed public consumer: source Switch/Radio snippets and nested remote Control → Switch/Radio snippets spread onto native span/div/dynamic elements with concrete authored attachment callbacks. Both Kit versions run it with strict exact-optional checking and `skipLibCheck: false`, beside the unchanged positive consumer and seven invalid namespace cases. This correction changes only erased types/imports; canonical renderer/ref, source registration, callback and native input bodies remain unchanged.

Authored radio render replacements use the actual semantic Radio.Root/RadioGroup. The facade omits only checked/defaultChecked/onCheckedChange from rendered radio props, preserving descriptor checked in render state and preserving option value/native name/ref. Group selection and its callbacks remain source-owned; a default Control supplies native radio adaptation. This projection does not promise generic raw input radio rendering.
