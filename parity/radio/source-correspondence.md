## Native differences and source evidence

Source Radio checks event-detail cancellation before committing group state. Native hidden onclick cancellation runs before native input/change, preserving that business contract without React checked tracking. The callback still receives an actual native click with modifiers. Secured Chromium at `a98f08e` ([run 37093701839](https://github.com/sveltery/base/actions/runs/37093701839)) observed React 19.2.8 emitting one native input and one change event even when the source callback cancels; native Svelte emits neither because its cancelable click is prevented before those phases. Both retain the original selected source value and successful input. The two original cross-framework zero-event expectations failed in that run (29/31 passed), and subsequent native characterizations assert the observed React two / Svelte zero events. These divergent supplements earn zero unchanged credit. No fabricated event object, activation replay or patched event methods are added.

An owner that rejects a controlled change leaves the source logical value unchanged. React 19.2.8 restores hidden checked state; native Svelte leaves the browser-activated radio successful until a reactive checked prop change. The Svelte observation is executed in `radio.test.ts`; the actual secured paired browser assertion verifies the React/Svelte observations separately and earns zero unchanged credit when different. Native reset returns each hidden input to its actual renderer-created defaultChecked state without inventing a reset callback or changing the source logical selected value; explicit default and controlled paired characterizations capture those defaults before activation. Hydration defaults likewise remain native. User decision basis: native Svelte/default HTML behavior and maintainability directive in `docs/source-porting.md`; no unrelated business bug fix is authorized here.

The optional native-name reader is a narrow remote integration seam from the Form owner: only the actual hidden DOM name changes. Source group logical names, Field registration, custom validators and errors stay unchanged. Standalone automatic remote `as="radio"` uses the remote Control's actual native radio adapter; semantic source Radio.Root overrides require an authored real RadioGroup. A separate group per option is not created.

Local development checks do not establish final source acceptance.
