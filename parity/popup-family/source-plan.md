# Popover, PreviewCard and Tooltip pre-code source plan

Original Base UI 1.8.0 is immutable commit `47b40521eab921c2756bf9bdb0b0f07fbfdb8c8c`, MIT. The isolated `source-popup-family` branch starts from actual project main `74f667da95ebc5670b0cc5bee38f2225e65fd0c0`. This checkpoint contains source evidence and implementation decisions only. No family runtime implementation, accepted source review, passing execution or unchanged assertion credit is claimed.

The public namespace inventory is Popover's eleven parts (Root, Trigger, Portal, Positioner, Popup, Arrow, Backdrop, Title, Description, Close, Viewport), PreviewCard's eight (Root, Portal, Trigger, Positioner, Popup, Arrow, Backdrop, Viewport), and Tooltip's eight (Root, Trigger, Portal, Positioner, Popup, Arrow, Provider, Viewport). Each also exports its own generic Handle and createHandle. All 27 component bodies, their inline types, three stores/handles, contexts, indexes and family CSS/data declarations have been read. Full test and inherited helper body reading remains pending; that reading and the coordinator's ownership decisions are required before runtime code.

The graph scanner reads immutable Git objects, not working-tree files. `source-graph.json` records a complete conservative 193-module AST runtime/type closure, its 188-module selected-symbol view and a separate 181-module TypeScript import-erasure projection. `test-helper-graph.json` separately records 753 conservative / 386 selected modules and a 370-module emitted projection. These projections are scope aids, not proof of the Original build or manual review. Named exports and star re-exports are resolved through declaration-free barrels; whole non-barrel bodies and external dependency entry points remain explicit. Unselected business exports from type/barrel fanout do not create implementation scope. `public-surface.json` separately retains CSS variable/data declaration modules outside entry-point imports. The exact source archive, body hashes, source links, declaration-site inventory and MIT license are evidence, never substitute runtime ports.

Parameterized expansion and loop expansion remain pending manual enumeration. Type specs also contain negative samples; their full bodies are archived and must be checked separately. All cases remain unported with zero ordinary credit. Existing shared ordinary aggregates are unchanged.

Implementation preserves the following Source boundaries:

1. Each Root creates its own distinct `PopoverStore`, `PreviewCardStore` or `TooltipStore` exactly once. Handles attach to that Root-owned store and retain inert fallback registries, stacked overlapping attachment, migration, no-op detached calls and anchored missing-trigger errors. Shared Store/NullStore/popup selectors/TriggerMap/BasePopupHandle/root helpers come from the canonical Source implementation. The current main's legacy `DialogRootController` and Dialog's private Root template are not a general popup abstraction.
2. Root composition retains its Original functions. Popover owns tree wrapping only outside another Popover, `usePopupRootSync`, patient-click timeout cleanup, actions, open/mounted interactions and callback/state order. PreviewCard similarly wraps its tree, closes when a resolved active trigger disappears, clears inline coordinates after unmount and clears unassociated open payload. Tooltip has no new tree wrapper: it synchronizes disabled/cursor/hoverable options, closes disabled open state, retains provider instant-type capture/restoration, clears unassociated payload and mounts interactions for cursor tracking even when closed.
3. Popover Trigger composes canonical hover/safePolygon/click/button/data-forwarding/open-method/focus-guard helpers in Source prop/ref order. Its default hover rest delay is 300ms, `openOnHover=false`, close delay 0. Popover Store preserves callback-before-cancellation-before-floating-dispatch, the 500ms patient-click timer and hover state flush purpose; Close carries the prior trigger into callback details only for close-press. Popup preserves original Close registration determining focus-manager modal eligibility, Toolbar composite key containment, hover-open focus-manager suppression, touch initial focus and both ARIA registrations. Positioner preserves trigger-change animation cancellation, true-modal/non-hover backdrop cutout and anchored touch/full-width scroll lock.
4. PreviewCard Trigger stays a native anchor, defaults delay to 600ms and close delay to 300ms, composes hover/focus/data-forwarding and inline pointer-rect capture. PreviewCard Store uses shared `applyPopupOpenChange` with `onBeforeDispatch` for inline capture after cancellation is checked. Positioner uses the Original local inline middleware, actual DOM client rects and default Floating UI platform. Popup remains hoverable with focusable props and no invented Dialog focus manager. Its backdrop is pointer-inert presentation. Portal uses `FloatingPortalLite`.
5. Tooltip Trigger composes provider delay, delay group, canonical hover/focus/data-forwarding and the actual nested-trigger/shadow-root algorithms. Disabled trigger marking does not add native disabled. It preserves nested-hover parent closure ownership, pending rest/open timer cancellation, local parent-area reentry timer, pointer-type checks, close-on-click pending-open cancellation and trigger override precedence. Tooltip Store uses shared `applyPopupOpenChange` and retains `cancelPendingOpen` as floating dispatch without a public state-change callback. Root's `useClientPoint` axis tracking uses its Original virtual-reference body and cleanup, including its zero-coordinate truthiness quirk. Positioner defaults to top and is pointer-inert for closed/both-axis/nonhoverable states. Popup has no invented dialog role or focus manager. Portal uses Lite.
6. Tooltip Provider remains its own delay context plus `FloatingDelayGroup`: Source `currentIdRef/currentContextRef`, initial/current delay references, timeout ownership, previous-tooltip close with `none`, instant phase and reopening/teardown cancellation. Provider timeout defaults to 400ms while the internal group's default is 0. Keep the two contexts' distinct responsibilities; shared hover state stays canonical.
7. All three Viewports use the same Original `usePopupViewport`/`usePopupAutoResize` body and content-transition composition, with family-specific instant types. All Positioners use canonical `useAnchorPositioning`/`useFloating` and `usePositioner`, one actual default `@floating-ui/dom` platform, current shared middleware/CSS helpers and real measured nodes. Arrow ref order remains family-specific (PreviewCard arrowRef before forwardedRef; the other two forwardedRef before arrowRef). No private geometry, hover, focus, state or navigation engine is introduced.

Native framework substitutions use Svelte context, derived reads, snippets, attachments/ref lifetimes, native event props, `ClassValue` and string CSS. Canonical plain Source Store is state authority; native `createSubscriber` adapts read/subscribe without a parallel snapshot store. Source helper synchronization is retained where required; React hook/debug/ref/render bookkeeping maps to native setup or lifecycle rather than a React emulation layer. Shared generated trigger/title/description IDs keep the `base-ui-` namespace through `useBaseUiId` and use `$props.id()` only for the native suffix. Root floating IDs follow Original `useId` ownership. Explicit undefined and null contracts, empty State assignability, generic payload inference and namespace/subpath types must pass packed consumers with `skipLibCheck:false` and exact optional properties.

`boundary-plan.json` names every module in the conservative source closure and every family declaration module, its proposed local/native boundary, actual main presence, helper owner and manual status. Candidate paths are plans, not installed ports. Business closure and type imports outside the diff must receive whole-body review before final acceptance.

Canonical ownership currently remains with the coordinator's designated developers. Menu exclusively owns shared floating drivers/store bridge, anchor-positioning, hover/focus/navigation/composite/constants, observer/previous-value helpers, viewport/resize/positioner/anchored scroll lock/trigger guards and listed append helpers. Dialog owns canonical root stores/tree/dismiss/click/focus-manager/full portal/popup root helpers. Tabs owns the exact public dimensions/transform bodies; preserve the Original zero-scale transform quirk. Shared rendering/ref/class/style helpers remain canonical. Public development PRs are not main acceptance. No shared file is edited before an explicit precise lease; each required dependency must land normally on actual main before final scope acceptance.

Proposed new ownership/leases, not yet authorized: `FloatingDelayGroup`/`useDelayGroup`, `useClientPoint`, `inlineRect`, `closePart`, `FloatingPortalLite` with actual canonical portal-node reuse, and the absent `applyPopupOpenChange` append in canonical popupStoreUtils. Popover's real optional `ToolbarRootContext` call requires the accepted context helper from its owner, not a whole Toolbar copy. All missing bodies keep dependent scope incomplete.

After source reading and ownership decisions, port missing selected dependencies before the three family modules; update actual used local graph/body hashes and source correspondence after each runtime checkpoint. Preserve suspected Source bugs until a physical exact-pin reproducer proves them; verified business corrections require a separate decision. Inherent native renderer differences retain actual Svelte/browser defaults, with separate witnesses and zero divergent unchanged credit.

Final gates are complete independent Source/native/maintainability review of the exact final head and inherited closure, meaningful DOM/SSR/hydration tests, installed root/subpath/render/ref/generic/negative public consumers, secured paired Chrome 153 (sandbox enabled, one worker, zero retries), full Verification and Standards, required configured review/CI and exact coordinator approval before the owner's normal expected-head merge. Failed raw browser logs remain evidence. No package publication is part of this work.
