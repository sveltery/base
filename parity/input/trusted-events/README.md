This supplements the programmatic dispatch matrix with real Chromium keystrokes against the actual Kit 2.70.3 remote form and its native Svelte comparator. The original direct field spreads, native form listener and consumer/value callbacks remain in place. No manual remote-state bridge or global event interception is used. Source and record hashes, immutable execution IDs and artifact provenance are in [evidence.json](evidence.json).

Secured checkpoint `289d89e41c16222f8d9dda08e4fe712c68b83cdc` ([CI 36982455436](https://github.com/sveltery/base/actions/runs/36982455436), browser job 110759808529) failed 15 of 548 executions. The native comparator's target tick ran while `eventPhase` was still 2 and retained the edit; Kit's phase-3 form listener then read the edit and updated its owner. Both default and replacement Input hosts restored the old owner between those phases, so Kit and the later delegated callbacks received the old value. Every trace retained `name="email"` and the correct form association. This was a local fidelity defect, not an accepted timing difference.

The browser can process promise work between native listener invocations when the JavaScript stack empties; the [HTML cleanup algorithm](https://html.spec.whatwg.org/multipage/webappapis.html#clean-up-after-running-script) specifies that checkpoint. A programmatic `dispatchEvent` inside a running script retains the outer stack, which is why the earlier DOM and programmatic-browser probes alone did not reproduce this failure.

The bounded repair waits for dispatch completion when a tick occurs during an active event. Native listeners and owner callbacks receive the edit first; settled restoration reads the latest owner. Host cleanup owns pending work. The programmatic matrix retains its original next-tick contract. Exact final-head secured execution and independent/configured reviews remain required.
