## Click and restoration fidelity

Actual React native checkbox/radio callbacks originate from `click`. Input uses the same native click backing event, string value request, reason `none`, render/consumer/value order, cancellation and Base-handler prevention. Its native onclick composition represents the checkable request channel; text continues to use native oninput. The default host restores after the composed callback even when Base handling is prevented. Replacement callbacks may continue reading native checked after props.onclick returns; a temporary root completion observer restores after that final callback work and removes itself after dispatch or teardown. Cleanup waits until dispatch finishes when a trusted event runs microtasks between listeners. It does not postpone checked restoration to tick or flush unrelated Svelte state.

For checked=false with consumer onClick.preventDefault and a rejected owner, the actual pin emits a click-backed value callback. Native activation rollback differs by execution environment: jsdom leaves the checkbox checked, while secured Chromium leaves it unchecked in both React and Base at checkpoint `2db8f57`. Browser expectations must follow the executed browser reference, separately from DOM-engine expectations. A canceled radio also retains its click-backed callback. Direct native Svelte differs because canceled activation emits no input event. The pin references React's related [preventDefault issue](https://github.com/facebook/react/issues/9023) in FieldControl. No additional local issue or private diagnostic payload is published by this work. A native input event alone does not manufacture a checkable value request, matching React's click-based change channel.

This source fidelity repair does not claim a new checked timing/default/canceled-click exception. I-02 remains value/defaultValue-specific and I-03 remains the accepted value restoration timing. Secured checkpoint `2db8f57` confirms a remaining direct Kit checkbox defect: click restoration hides the edit from Kit's later native input listener and its descriptor-only owner does not update. The native comparator updates and submits successfully. Replacement callbacks that stop click propagation also expose an unresolved completion boundary. These are blocked prerequisites, not accepted limitations or a claim that checked Kit spread support is complete. A necessary substitution requires its own concrete source/native evidence and compatibility decision.
