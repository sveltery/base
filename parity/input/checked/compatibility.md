## Click and restoration fidelity

Actual React native checkbox/radio callbacks originate from `click`. Input uses the same native click backing event, string value request, reason `none`, render/consumer/value order, cancellation and Base-handler prevention. Its native onclick composition represents the checkable request channel; text continues to use native oninput. The default host restores after the composed callback even when Base handling is prevented. Replacement callbacks may continue reading native checked after props.onclick returns; a temporary root completion observer restores after that final callback work and removes itself after dispatch or teardown. Cleanup waits until dispatch finishes when a trusted event runs microtasks between listeners. It does not postpone checked restoration to tick or flush unrelated Svelte state.

For checked=false with consumer onClick.preventDefault and a rejected owner, the pin emits a click-backed value callback and leaves the DOM checkbox checked after native activation rollback. Input preserves this source quirk by restoring before activation rollback; a canceled radio also retains its click-backed callback. Direct native Svelte differs because canceled activation emits no input event. The pin references React's related [preventDefault issue](https://github.com/facebook/react/issues/9023) in FieldControl. No additional local issue or private diagnostic payload is published by this work. A native input event alone does not manufacture a checkable value request, matching React's click-based change channel.

This source fidelity repair does not claim a new checked timing/default/canceled-click exception. I-02 remains value/defaultValue-specific and I-03 remains the accepted value restoration timing. Actual Kit checked descriptor spreads and direct native comparators test a separate boundary: native Kit form input listeners run after click handlers, so synchronous source restoration may affect their implicit owner updates. These browser witnesses are diagnostic prerequisites, not a claim that checked Kit spread support is complete. If they expose a necessary substitution, its observable source/native boundary and alternatives require a specific compatibility decision rather than inferred approval.
