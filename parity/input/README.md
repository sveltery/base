## Reset and controlled scheduling differences

Before the runtime existed, three native Svelte DOM baselines and three actual pinned React DOM characterizations passed. [Reset observations](reset-baseline.json) record exact defaults and version/source evidence. React controlled `value="owner"` uses `defaultValue="owner"`, even when the supplied default is seed. Svelte value alone has an empty reset default; a supplied seed remains the reset default. Local native reset leaves the owner prop unchanged and emits no value callback. Canceled reset preserves the edited DOM. This user-directed native behavior is I-02 in the [compatibility register](../../docs/upstream-differences.md); divergent assertions earn no parity credit.

Controlled native edits settle through an attachment-owned input listener after Svelte's tick. React's event system restores rejected/prevented edits and rewritten values before dispatch returns; Svelte exposes the edit immediately after dispatch and the owner value after tick. Tests record both observations. The listener covers render/consumer prevention and composition, is removed with its host, and avoids overwriting the next host after replacement or teardown. A synchronous wrapper would be bypassed by render-owned prevention; document interception would add propagation/shadow ownership changes. This bounded I-03 scheduling substitution is proposed, with no specific acceptance recorded. It earns no divergent credit.
