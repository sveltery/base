## API and framework decision

Generic Root/Trigger components use `RootProps<Payload>` and `TriggerProps<Payload>`. Root children receive the complete pinned root-state object `{ payload: Payload | undefined }`; no-argument snippets may ignore it. Proposed public `Dialog.Handle` and `Dialog.createHandle` aliases expose the concrete generic class/factory. Their payload type parameter has no default, matching the pinned declarations; construction/factory calls can infer unknown. The [type fixture](../../packages/base/tests/DialogPayloadTypes.svelte) verifies no-argument snippets, strongly typed payload snippets and direct children; [negative checks](../../packages/base/tests/dialog-handle.types.ts) reject wrong payloads and missing bare Handle type arguments.

PM's [durable scoped decision](https://github.com/sveltery/base/pull/42#pullrequestreview-5397221448), anchored at `850a4db`, approves this native component/snippet design within the framework baseline. It also permits replay-specific R1399 to remain individually framework-unimplemented/uncredited, retaining its complete actual strict source body and expected two callbacks. Native completion remains a separately labelled single-callback lifecycle supplement. This is delegated PM design/scope authority, not explicit user acceptance, blanket React type parity or final merge approval. Public exports and package integration remain queued behind CSPProvider/UseRender.
