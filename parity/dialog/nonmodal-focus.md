## Selected source contracts

- [FloatingPortal.tsx:183–299](https://github.com/mui/base-ui/blob/47b40521eab921c2756bf9bdb0b0f07fbfdb8c8c/packages/react/src/floating-ui-react/components/FloatingPortal.tsx#L183): open nonmodal guards sit at the logical Portal position, independently of the owning Trigger. Portal capture focusin/focusout suppresses physical portal tabbability while focus is outside, restoring saved attributes on entry/reopen. Forward outside guard moves to the next control and explicitly requests `focus-out` with the native focusin event; backward guard moves to the previous control.
- [FloatingFocusManager.tsx:954–1010](https://github.com/mui/base-ui/blob/47b40521eab921c2756bf9bdb0b0f07fbfdb8c8c/packages/react/src/floating-ui-react/components/FloatingFocusManager.tsx#L954): guards around Popup connect the two DOM locations. Reverse exit returns through the before-outside guard; forward exit suppresses focus return when focus-out closing is enabled. `modal !== false` uses trapping rather than logical nonmodal order.
- [FloatingFocusManager.tsx:406–575](https://github.com/mui/base-ui/blob/47b40521eab921c2756bf9bdb0b0f07fbfdb8c8c/packages/react/src/floating-ui-react/components/FloatingFocusManager.tsx#L406): native focusout checks relatedTarget asynchronously; floating/portal, registered Triggers and owned guards are inside. Null relatedTarget alone does not dismiss. Popup capture tracks movement inside the logical tree. Pointer suppression and previous-focus exclusion also affect dismissal. Actual hosted React preserves programmatic Popup-to-outside focus (capture marks the logical tree), but owning-Trigger-to-outside focus requests close with the original native focusout event. Blurring to null alone does not dismiss; an inactive Trigger has no owning-reference focusout listener.
- [DialogPopup.tsx:96–107](https://github.com/mui/base-ui/blob/47b40521eab921c2756bf9bdb0b0f07fbfdb8c8c/packages/react/src/dialog/popup/DialogPopup.tsx#L96): mounted presence enables focus management, `modal !== false` traps, and `disablePointerDismissal` disables focus-out closing as well as pointer dismissal. Disabling dismissal does not disable logical Tab order.
- [tabbable.ts](https://github.com/mui/base-ui/blob/47b40521eab921c2756bf9bdb0b0f07fbfdb8c8c/packages/react/src/floating-ui-react/utils/tabbable.ts): next/previous navigation uses the current focus in document order; reference is a fallback. Suppression stores/restores original tabindex. It does not reorder Popup next to the active Trigger.

## Bounded approach and evidence

The test-first head `ee37c7b65de1cca20b9a95280f9d6d685e0ce772` ran in [secured hosted CI 36861245120](https://github.com/sveltery/base/actions/runs/36861245120). Standards/Verification passed; browser execution exposed six Svelte logical Tab failures with all six corresponding real React scenarios passing. The exploratory native focus trace confirmed Popup-to-outside remains open in React but closes Svelte; Trigger-to-outside closes React using focusout, original target and relatedTarget. Strict paired regressions now replace exploration. The new trap-focus assertion failed in both adapters because it checked aria-hidden directly on an outside button rather than inherited isolation. It was corrected to effective ancestor aria-hidden; all Tab, focus, scroll and trusted outside-pointer assertions remain. All existing browser tests passed in that baseline run.

Runtime: Portal keeps a comment at its logical position before moving its wrapper. A reactive private Portal focus-manager reference installs the four native guards only while open and nonmodal. Guard nodes, saved tabindex attributes and handlers belong to that pair; cleanup restores attributes and removes every guard on close, modality change or removal. The Popup supplies its owning-reference fallback dynamically, following owner changes. Native owning-Trigger focusout checks relatedTarget in a microtask, excludes registered Triggers/portal/owned guards/ancestor popup references, and delegates through the existing topmost overlay stack. Popup programmatic exits preserve the logical tree; guards explicitly handle forward Tab dismissal. Existing modal trapping, scroll locking, isolation/live-region ownership and presence code are preserved. No new per-document registry, public props, dependencies, workflows or browser-security settings.

Independent review caught a missing document-edge reference fallback. A paired browser regression was committed before adding the dynamic fallback to the local helper. Generic FloatingFocusManager empty-popup tabindex management was also inspected; its early return for Dialog's existing explicit tabindex=-1 means a generic inference of tabindex=0 would be incorrect, so no guessed Dialog behavior was added.

All scenarios in `tests/browser/dialog-nonmodal-focus.spec.ts` are source-derived supplements. No complete upstream declaration credit is claimed: global **15/633**, Dialog **11/175**, expanded **13/371** remain unchanged. Detached handles, Viewport, Drawer/Toast and arbitrary external portal mutations are excluded. Material public API deviation or a large rewrite is a stop gate.

Current validation comprises 26 paired browser executions and 16 paired DOM event/lifecycle diagnostics. Local full verification passes 13 script/SSR tests, 19 runtime tests and 96 DOM tests, zero library/fixture diagnostics, SSR/client builds, runtime imports and isolated tarball/SSR consumers. Both pinned inventory checks retain unchanged source bytes/counts. Hosted final-head checks and independent Sol/high review remain the merge gates; their exact commit/run evidence is recorded in PR #9 when complete.

The bounded tests cover ordinary native buttons/inputs, one contained Popup, multiple contained Triggers, initialFocus=false entry, disabled dismissal, keepMounted cycles, document-end fallback, native guard-event payload, null relatedTarget, programmatic focus and a nested modal child using the default nested portal. Explicit containers/shadow roots, detached handles, arbitrary relocation/mutation, full canceled/held focus-out combinations and generic focusability conformance remain unverified by this slice.
