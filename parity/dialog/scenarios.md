## Common fixture contract

The adapter builds real library parts, never a surrogate Dialog. No adapter exists in this branch. These fixture names specify logical topology and observables, not a proposed Svelte API:

- **F-contained:** Root; owning Trigger named Open/test ID trigger; Portal; optional user Backdrop/test ID backdrop; Popup/role dialog; Title, Description, Close as required by each source. Popup/portal/root props can be updated by the host. The baseline has animations disabled; animation scenarios explicitly enable them and restore that setting on teardown.
- **F-detached:** the same Root/Portal/Popup, with a real shared handle connecting a Trigger outside the Root. **F-multiple-detached:** the upstream two-trigger variant, retaining its per-trigger IDs/payloads. `R` tests under `when using $name` run separately for all three fixtures. Do not collapse them into one execution.
- **F-focus:** outside-before and outside-after inputs/buttons, Trigger, Portal/Popup, ordered inner inputs and Close; explicit element references/callbacks chosen by the source case. Use browser `activeElement` in the appropriate owner document/shadow root.
- **F-nested:** independent Root/store per logical parent/child, each with its own Trigger/Portal/Popup/Close. DOM portaling does not erase logical ancestry. Cross-type Menu, Select, AlertDialog, Drawer, NumberField and ScrollArea scenarios retain those actual dependencies and remain blocked until supported; a Dialog substitute is not a port.
- **F-hydration:** server render plus actual client hydration of the same logical tree/handle, including a gate capable of delaying the detached Trigger. Capture server attributes before hydration and client console errors. A client mount is not hydration.

All fixtures expose actual popup/trigger/portal/backdrop/viewport nodes; callback logs retain boolean state, reason, exact native event and owning trigger identity; separate observation of the internal openchange dispatch is needed for R:555/582. A browser adapter must operate real keyboard/pointer/touch input as specified below and preserve individual source assertions. Teardown removes fixture roots, explicit portal hosts, listeners and clocks; it restores animation flags and CSS.

**order-01 — source-derived supplement, unported:** `DialogStore.ts:setOpen` calls consumer first, checks cancellation, then dispatches internal openchange and updates internal state. Instrument the real implementation through a dedicated observation hook supplied by the implementation owner: consumer observes pre-change effective state; accepted request logs consumer → internal dispatch → settled state; canceled open/close logs consumer only. Assert native event/trigger identity and live cancellation flags. Preserve a prior owning trigger during close/focus return. This is an implementation contract, not a test assertion claimed from R:535. Controlled state uses popup selectors `openProp ?? open`, not generic useControlled's initial-mode rules. Hold `open=false` during a trigger request and assert no visible opening until owner update; hold `open=true` during a close request and assert it remains visible until owner update. Do not claim these supplements as upstream ports.

**order-02 — executable prerequisite:** [dedicated native merge tests](../../packages/base/tests/dialog-merge-prerequisites.test.ts) port merge test assertion meanings for right-to-left ordering, undefined handlers, and both prevention positions. They establish utility evidence only; they do not establish that a real Trigger/Close composes props correctly.
