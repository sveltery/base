# Menu, ContextMenu and Menubar source plan

This is the pre-code checkpoint for the complete cohesive family. NavigationMenu remains separate. Original Base UI 1.8.0 is pinned to `47b40521eab921c2756bf9bdb0b0f07fbfdb8c8c`, MIT; all selected source and test/helper bodies are archived intact under `upstream/`, with immutable hashes and links in the graphs. Archival bodies establish provenance only. No ordinary assertion credit, behavior acceptance or missing-helper completion is claimed.

`source-graph.json` records the complete recursively traced runtime/type import/re-export closure from all three public entries. `test-helper-graph.json` separately records the complete test/public-type/helper closure; full-barrel fanout is intentionally conservative and symbol selections remain recorded. `boundary-plan.json` records every source module's planned business/native boundary. Some candidate filenames will be reconciled to actual canonical paths before final review; the initial plan does not claim these ports already exist.

Implementation order and checks:

1. Consume the already public Dialog development checkpoint `ad19bb37f6e9ff12b7ac68b27709042130c47b7c` (PR42) for its single canonical Store/FloatingRootStore/tree/events/popupStore/TriggerMap/BasePopupHandle/useClick/useDismiss/FloatingFocusManager/Portal bodies. This is an explicitly unaccepted development dependency, not main acceptance. Do not extract a private Menu fork. Dialog Root's template remains under its owner's lease.
2. Connect existing private anchor-positioning to that root store and tree through Original `useFloatingWithStore`/`useBaseUIFloating`: reference/domReference/floating ownership, floatingContext publication and tree node context. Default `@floating-ui/dom` platform and current Original-derived middleware bodies remain authoritative. Apply only the precise shared-helper lease authorized by the coordinator.
3. Port the actual selected `useListNavigation`, `useTypeahead`, `useFocus`, hover interaction shared state/reference/floating helpers and `safePolygon`. Keep original orientation/RTL/nested tree navigation, virtual-event handling, focus scheduling, string matching/reset, pointer shielding, delayed cancellation and cleanup. Reuse Composite utilities and canonical timers/event helpers, not a competing controller.
4. Port MenuStore/Handle and all Menu parts, contexts and types. MenuRoot preserves popup composition, parent classification, seeds, setOpen ordering, cancellation, native delayed touch guards, tree dismissal/navigation/typeahead and imperative handle lifecycle. Trigger preserves detached registration/data migration, hover/click/focus composition, pointer-release guards and Menubar CompositeItem. Items preserve real disabled navigation, hover tree relays, modifier clicks, checkbox/radio callbacks and source close semantics. Positioner preserves sibling/parent/item-hover tree coordination, transition/scroll-lock/backdrop and CompositeList. Popup preserves full shared focus manager and hover composition. Viewport preserves Original resize/content-transition composition.
5. ContextMenuRoot remains a thin provider and MenuRoot composition with reset menu context; Trigger preserves virtual rect anchors, long-press movement cancellation, document contextmenu prevention, mac control-click/release behavior through the original native event branches, abort controllers and root-owner checks. Positioner uses Original fixed positioning and context offsets. Public aliases reuse Menu's actual part/type bodies.
6. Menubar uses canonical CompositeRoot/Item and a real FloatingTree/Node. Preserve menuopenchange parent-node filtering, sibling/list-navigation retention, modal/disabled/orientation state and keyboard relay.
7. Reconcile actual used local runtime/type graph, original assertions ledger and correspondence after implementing; independent review must manually compare every full used body including inherited dependencies. Preserve original expectation bytes and separate ordinary/parameterized/conformance/type/supplemental accounting. Tests alone never establish source fidelity.

Native Svelte substitutions are state/derived/effect/context/tick, snippets, binding/attachments, native event keys and CSS strings with explicit units. DEV uses `esm-env`. Keep native element behavior; no React state/ref/synthetic-event/StrictMode adapter is introduced. Suspected business bugs stay source-identical unless an actual paired pinned-source reproduction proves a separately authorized difference.

Final gates include meaningful native DOM/SSR/hydration and actual installed tarball root/subpath/render/ref/generic/negative type consumers with `skipLibCheck:false`, secured Chrome 153 paired behavior (sandbox on, one worker, zero retries, preserved raw failure JSON/traces), full verification and Standards and configured CI on exact reviewed head. A quota exception, if applicable, is scoped waived evidence and never a passed review. Developer owns regular commits, its public PR and the normal expected-head merge after independent and Root exact-head approval; no package publication.
