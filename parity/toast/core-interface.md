## Public surface

`import { Toast } from '@sveltery/base'` or `import { createToastManager } from '@sveltery/base/toast'`. The public toast entry exports only the manager factory plus `ToastManager`, `ToastObject`, `ToastContent`, `ToastActionProps`, add/update/promise option types and `ToastManagerFacade` types. Store/facade factories and manager event types are internal source modules, not named public exports. No `getToastManager`, `useToastManager`, Provider or parts runtime export is invented.

`createToastManager<Data extends object = any>()` owns a synchronous Set channel. Its methods retain method-level `<T extends Data = Data>` generics. No queue, state array, timer or global store belongs to it. Add before subscription is lost. `promise` returns the original promise when unattached, or the last subscriber's synchronously handed-off handled promise when attached. Multiple Providers independently resolve options and own their resulting state/timers; a promise's loading ID is allocated by each store. Data objects and callable data are stored without invoking or merging them.

The private, pinned `' subscribe'` key is retained. Its event is a discriminated union: `add` carries a starting ToastObject with ID; `update` carries `{ id, updates }`; `close` carries `{ id?: string }`; `promise` carries loading/success/error options plus `{ promise, setPromise }`. Private payload data/result generics are erased as in upstream. Set delivery is live and synchronous: unsubscription and reentrant emission take effect immediately, and newly added listeners can receive the current event. Listener exceptions propagate and stop that emission, as pinned.

## Internal Provider adapter contract

The DOM owner may import `ToastStore`, `selectors`, `State`, `StoredToast`, `InitialState` from `store.ts`, and `createToastFacade<Data>(store)` from `facade.ts` while implementing the future public context accessor. Construct **one store per Provider**. Defaults are empty toasts, timeout 5000, limit 3, hovering/focused false and window focused true. Initial toast arrays are fixture/internal state, not a public initial-toasts Provider prop.

| Operation | Contract |
| --- | --- |
| `getSnapshot()` / read-only `state` getter | Stable object until a published update. Read inside a Svelte reaction tracks `createSubscriber`; no effect copies state. Snapshots/arrays/maps are immutable by convention and must not be mutated by consumers. |
| `subscribe(() => void)` | Synchronous invalidation after commit; no initial callback. Read `getSnapshot()` in the callback. Returns idempotent unsubscribe. Internal Svelte tracking shares one external subscription among reactive consumers and cleans it up with their reactions. |
| `attachManager(manager?)` | Replace old attachment, no replay. Returns an attachment-specific cleanup; stale cleanup cannot disconnect a replacement. Dispose also detaches. Rejections from each Provider's independent handled-promise branch are observed; the original returned promise still rejects with the same error. |
| `syncProviderProps(timeout, limit)` | Explicit committed-input synchronization; recompute limited metadata on limit change. Existing timer deadlines do not change merely because the default changes. The DOM owner must verify committed-prop ordering before descendant mount-time adds and aborted branches with real fixtures. |
| `addToast`, `updateToast`, `closeToast`, `promiseToast` | Bound callbacks. Add/upsert preserves newest-first order and updateKey. Ending writes are ignored. Close publishes ending state and zero height before onClose; physical removal invokes onRemove separately. |
| `updateToastInternal(id, updates, resetTimer?, markUpdated?)` | Internal height/node/transition registration. Ending entries reject all writes, including observer height writes with undefined transition status. Public update excludes these internal fields. |
| `set`, `update` | Internal interaction/viewport/focus registration; no automatic pause/resume policy. DOM adapter must update interaction flags and call timer methods in the pinned owner-window/event order. Never replace `toasts`/`toastMetadata` through these general interaction setters. |
| `pauseTimers()`, `resumeTimers()` | Per-store timers; fake-clock-tested repeated pause, explicit timeout resets, scheduling during expanded/blurred state and throttled wall-clock restart. Timer pause is distinct from interaction flags, matching source callers. |
| `getLifecycle(id)` / `removeToast(id, skipOnRemove?, expectedLifecycle?)` | Capture the opaque token when a Root begins a lifecycle. Upsert preserves it; re-add after ending replaces it. Pass the captured token on exit completion so an old animation cannot remove the replacement. Suppressing old onRemove on ending-ID re-add is retained. |
| `dispose()` / `disposeEffect()` | Final, idempotent teardown: clear timers, detach manager and clear subscribers/lifecycle bookkeeping. No onClose/onRemove fires. Pending promise settlement preserves value/error and invokes its resolver but cannot mutate disposed state or create a timer. `disposeEffect()` returns dispose for retained test compatibility; it is not a reusable React mount lifecycle. |
| `createToastFacade<Data>(store)` | Stable `{ get toasts(), add, update, close, promise }` with live reactive reads and bound methods. The future `getToastManager<Data>()` should read Provider context during component initialization. Destructured `toasts` is an ordinary snapshot. |

Selectors retain ID-based toast/reference equality, DOM index, active visible index (-1 ending), cumulative height offset, empty/focused/expanded/out-of-focus state. Ending entries do not consume limit; limited entries remain in the array.

## Exact adaptations and pending compatibility

- ReactStore is replaced with immutable per-instance snapshots and Svelte `createSubscriber`. Native setTimeout/clearTimeout plus Date.now implement the pinned Timeout start/clear behavior. Timers are committed **before subscriber notification** so reentrant close/update/remove/dispose cannot leave a stale timer. All retained clock boundaries execute unchanged.
- Native imperative IDs use a per-instance counter/random seed instead of the upstream module counter/random ID algorithm. Truthy explicit IDs and empty-ID generation are retained. These are imperative notification IDs, not hydration label IDs: DOM parts must use SSR-stable Svelte component IDs for their own labels.
- Ending-ID re-add is published atomically rather than notifying an intermediate removal. It preserves interaction flags while replacing the lifecycle. The old onRemove is suppressed as upstream. Lifecycle completion tokens are an added internal protection and require actual animation fixtures in the DOM slice.
- Physical removal clears its timer and commits before onRemove. Upstream invokes onRemove before removal and does not clear that timer here. The new order makes recursive removal exactly once and retains callback additions. Code reading the toast from onRemove observes absence; this is an explicit callback-order deviation, tested as a supplement and awaiting parent compatibility review.
- Disposal is final and blocks all subsequent writes. Pinned disposeEffect only clears timers. Promise branch rejection observers avoid unhandled orphan branches with multiple consumers. Resolver exceptions otherwise follow pinned `.then(...).catch(...)`: a success-resolver exception reaches the error resolver; error-resolver exceptions reject the returned promise.
- Svelte content is string/number/boolean/null/Snippet, not ReactNode. Action props are Svelte button attributes with lowercase events and the existing preventBaseUIHandler event type; children use that content union. Internal ref is the actual HTMLElement/null. None of these types certify actual rendering, buttons, label registration or focus semantics.
- `positionerProps` is intentionally absent from this slice's ToastObject: no anchored Positioner API is implemented. A coordinated types/parts change must add its full supported Svelte contract. Do not infer anchored, gesture, render/ref/class or React syntax parity from these exports.
- Pinned store DOM focus transfer, restore-to-previous-element and document-touch handling are **deferred** to the DOM owner. State retains viewport/previous HTMLElement references without accessing globals. The DOM adapter must add explicit close focus management and touch routing; subscribe alone is not a replacement for those methods. No overlay edit or Toast/Dialog coexistence guarantee is included.
