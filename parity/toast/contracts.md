## Manager option types

Exact React declarations and the two type specs are hashed/traced in the inventory. [useToastManager.ts:31–197](https://github.com/mui/base-ui/blob/47b40521eab921c2756bf9bdb0b0f07fbfdb8c8c/packages/react/src/toast/useToastManager.ts#L31) defines the public shapes:

- `ToastObject<Data extends object>`: id, ref, title, description, type, timeout, priority (low/high), transitionStatus (starting/ending/undefined), updateKey, limited, height, onClose/onRemove, actionProps, positionerProps, data. Callable data is valid object data and must be stored without invoking it.
- `add<T extends Data>(options): string`: optional id; excludes height/ref/limited/updateKey (the upstream Omit also names `animation`, although ToastObject has no animation property). Starting transition may be supplied publicly but the store overrides it on insertion. Existing truthy ID upserts; empty ID requests generation.
- `update<T extends Data>(id, options | (prevToast) => options): void`: excludes id/ref/height/transitionStatus/limited/updateKey; each `data` replaces the whole value. Missing/ending ID never invokes an updater. Updaters can mutate the store, so read current state again before merging their result.
- `close(id?): void`: omitted ID closes all. There is **no cancelable Toast close event or `onOpenChange` detail**; onClose is a notification after ending state is published. Native default prevention, `preventBaseUIHandler()` on a composed Close event, and pointercancel/gesture reversal are separate channels. Do not invent Dialog `cancel()` semantics.
- `promise<Value,T>(Promise<Value>, {loading,success,error}): Promise<Value>`: loading string/object; success/error string/object/result callback. A string becomes **description**, not title. Loading type persists without timer; success/error set their type and explicitly assign resolved timeout (including undefined), so a loading timeout=0 does not leak into settlement. Return original value / reject original error. Update ignores dismissed/removed loading ID; settlement cannot reopen it. Unattached external manager returns the input promise unchanged.

The test-only data spec retains every positive exact-type assertion and all four expected errors. Its opaque content/ref/action/positioner fields do not establish a final Svelte public API. For the first Svelte proposal, title/description accept renderable text/number and typed snippets, action props use Svelte button attributes and lowercase events, ref resolves the actual node through attachment/bind:ref, children use snippets, class/style follow existing Dialog's declared string/callback policy. Rich ReactNode, object-style/render/ref APIs require explicit mapped tests, never silent React syntax claims. Data defaults and method-level generics should retain the pinned manager shape.

## Store, time, announcements and gestures

[store.ts](https://github.com/mui/base-ui/blob/47b40521eab921c2756bf9bdb0b0f07fbfdb8c8c/packages/react/src/toast/store.ts) is the authority for the pure algorithms exercised in this preparation:

1. New entries prepend with updateKey=0. Active existing-ID add updates **in place**, strips id/transitionStatus from the update, increments updateKey and refreshes the timer even with the same timeout. Existing ending ID is removed with old onRemove suppressed, then prepended as a fresh lifecycle. No text-based deduplication exists; callers provide a stable ID.
2. Mark newest active `limit` visible, older active entries limited; ending entries do not consume limit. Limiting retains entries. Close publishes ending/height=0 and recalculates limited flags before callbacks, making reentrant close exactly once. onRemove runs only on physical removal and is a no-op for missing IDs; focus transfer is a separate DOM responsibility.
3. Timer uses per-toast timeout nullish fallback to Provider default. Zero/nonpositive duration and type=loading have no auto-close timer. An explicit timeout update resets even if unchanged; type change away from loading schedules; unrelated update preserves remaining time. Provider timeout synchronization changes the default for subsequent operations; it does not rewrite existing timer deadlines merely by changing the prop.
4. Pause subtracts elapsed active time from remaining; repeated pauses are idempotent. Resume stamps a fresh start. If throttled wall time made remaining<=0, resume restarts full delay as pinned. Scheduling during hovering/focused/window-blurred state leaves timer unstarted. Last-timer clearing/firing resets paused state; disposal clears timers.
5. Viewport hover/focus-visible/window blur pause. Mouseleave can defer collapse through ending presence or active touch; blur-related collapse must not restart while window remains blurred. Shift+Tab return inside viewport stays paused. A touch outside explicitly resumes and clears interaction even when window-focus state is unchanged; mouse outside does not. Owner listeners rebind once across empty cycles and clean up.
6. Viewport polite updates and urgent alert nodes, Root role/aria-hidden, Close hidden/revealed state and live label registration must be tested together. Same-ID update retains a node but changes content/updateKey. Screen-reader delivery is not proven by textContent or compile success; retain structural assertions and record any manual AT evidence separately.
7. Stack metadata maps ID to DOM index, active visible index (-1 for ending), offsetY accumulated from heights. Root CSS index uses DOM index while ending, visible index otherwise; --toast-offset-y/height, viewport --toast-frontmost-height and state attributes require real measurements. Empty/recreated/reordered/key-reused objects and ending height writes have distinct cases.
8. [Root gesture code:35–41](https://github.com/mui/base-ui/blob/47b40521eab921c2756bf9bdb0b0f07fbfdb8c8c/packages/react/src/toast/root/ToastRoot.tsx#L35): default directions down/right; >40px dismissal, reversal cancel threshold 10px, first movement locks axis, opposite movement is damped, primary button only, active pointer identity/capture and document release/cancel cleanup. Native touchmove is prevented only during active drag; both swipe-ignore attributes are honored. Anchored means anchor !== undefined, including null, and disables swipe. This is displacement-based; do not invent a velocity threshold. Gesture and anchored plans are traced **unported** and deferred from the first slice.
