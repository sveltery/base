## Behavior and Svelte adaptations

The accepted framework API baseline is limited to: className to class; React render elements to Svelte snippets; refs/actionsRef to Svelte bindings and attachments; synthetic to native events; current CSS strings instead of React style objects. [Compatibility entry T-01](../../docs/upstream-differences.md#t-01-proposed-toast-frameworkapi-substitutions) records the decision and its scope. Ordinary prop names, defaults and semantics remain the pinned contract. This acceptance does not extend to behavioral fixes, other API changes, T-02 timing deviations or incomplete contracts.

Provider owns one store and stable facade. Pre effects synchronize committed inputs and attachment-specific manager subscriptions. Teardown disposes timers and registrations without callbacks. SSR does not attach managers or access browser globals; Providers and requests remain isolated. Facade getters track live state; destructured arrays are snapshots.

Root registers its actual native node, measures mount/rebind height and exposes pinned roles, labels, inert limits, priority visibility, attributes and zero-swipe stack variables. Content owns its owner-window ResizeObserver/MutationObserver and cleanup. Animation observation captures inherited lifecycle tokens and cancels its own frames/completions on invalidation. Native refs need explicit registration cleanup, including ending/unmounted and index-rebound Roots, because Svelte's HTMLElement ref replaces React's mutable ref object. This preserves the DOM ownership contract. Inherited lifecycle/atomic-replacement/disposal differences from merged core are documented in [core-interface.md](core-interface.md); this slice does not revert them.

Viewport follows the pinned per-close next-then-previous non-ending scan after each close's complete callback loop. Nested requests each invoke focus management. It reads the current owner document's composed active/focus-visible element. Store-to-Viewport registration adapts React's store-owned DOM method and uses registration-specific cleanup. Scheduled window-focus publication survives empty-store listener cleanup and is canceled only on component teardown, matching the pinned timeout hook. React suppresses native removal focusout during commits; Svelte forwards it while its source is still connected. The native adapter settles null-relatedTarget releases in a microtask and requires the same registered, connected Viewport, connected event source and unchanged focus-event version and registration token. Subsequent native interactions settle pending connected blur first, preserving event order. Removal therefore preserves the pinned pause, explicit blur of a surviving element releases it, and fresh focus invalidates stale release. This timing adapter distinguishes ordinary native detach from consumer blur of a surviving element; non-null-target blur remains synchronous. In controlled JSdom, explicit blur followed by Viewport removal in the same turn releases React’s pause but retains Svelte’s; native Chromium execution of the equivalent fixture releases both. This model/platform timing boundary is tracked in [#21](https://github.com/sveltery/base/issues/21), with the distinct executed paired evidence; complete lifecycle parity is not claimed. Event handlers read live Svelte store state rather than React rendered closures; exact same-batch closure behavior is unported. Executed React/Svelte evidence shows blur then Root focus in one uncommitted batch can resume only React’s timer; an explicit framework commit between the events retains focus and pause in both. Paired native evidence distinguishes this adapter from an improvement that clears interaction state on detach. It adds no transaction-origin capture, same-ID preference, successor-draining loop or silent-detach focus recovery. Pinned limited-entry scanning, individual interaction resumption, initially focused-window default and empty-store listener detach/rebind remain observable. Frontmost height reads the array head, including its zero height while ending.
