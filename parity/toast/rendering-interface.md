## Ownership and observable behavior

Provider creates one store and stable facade during initialization. Pre effects synchronize committed timeout/limit inputs before descendant pre/mount adds and replace manager subscriptions with attachment-specific cleanup. Destruction disposes timers, subscriptions and registrations without lifecycle callbacks. Server rendering never attaches managers or accesses browser globals; Providers/requests have independent state. Facade getters track the live store without copied-state effects. Destructured toast arrays remain ordinary snapshots.

Root derives metadata directly from the store and renders the supplied toast, including spread clones and index-keyed list rebinding. It registers the actual node and measures natural height. Content owns owner-window ResizeObserver/MutationObserver and disconnects both; observer updates flush synchronously, while ending entries reject height/ref/status writes. Root exposes pinned roles, labels, native inert limits, priority visibility, state attributes and stack/zero-swipe CSS variables. High-priority announcements use separate atomic alerts while unfocused; structural checks establish no assistive-technology speech claim.

Exit observation waits an owner-window frame for real animations, waits for finished promises and rechecks cancellation replacements. Each observation captures an opaque lifecycle token and aborts its own frame/completion on invalidation/unmount. An old animation cannot remove an ending-ID replacement, including when the keyed Root remains. onRemove runs while the toast and DOM Root remain present, before removal publication. onClose runs after ending publication; callback ordering is preserved.

Root unregisters only its own actual node/lifecycle, including during ending when ordinary height/status writes are forbidden. Index-keyed rebinding also clears the previous registration. Conditional Root unmount retains ending presence in the store without retaining a disconnected focus target. Window focus/blur listeners remain attached while the Viewport is mounted, including empty transitions. Delayed focus publication rechecks actual owner-document focus, so descendant focus in a blurred document cannot resume timers. It resumes any timer added in the interim only when current interaction permits; a later blur cancels that publication. Attachment and listener installation read the actual owner document hasFocus state, including an already blurred owner. Future toasts therefore use the observed owner-window state.

Viewport owns its registration, window F6/focus/blur listeners, document outside-touch listener, delayed owner-window focus work and guards. Empty transitions clean up F6/outside-touch listeners; unmount cleans up all listeners and pending work. Hover/focus-visible/window pause, deferred mouseleave during exit/touch and pointer-end routing follow pinned caller policy. F6 enters Notifications; guards enter non-ending/non-limited Roots; Shift+Tab returns prior focus; Root Escape only closes when composed active focus is contained in that Root. Scoped Toast focus helpers do not change shared Dialog focus. Intentional uncredited corrections to pinned upstream behavior keep timers paused until hover, keyboard focus and window blur all end; each interaction is cleared before fresh pause state is checked. Initial owner-document focus sampling is also an explicit uncredited correction; Provider initialization remains SSR-safe.

Internal `setCloseFocusHandler` returns registration-specific cleanup, even for identical callback registrations. Store timer, external-manager and facade closes invoke the current registration synchronously **after the complete outer onClose loop**. Nested closes share that transaction, including closes during render-commit removal callbacks; the transaction captures the actual focused Root, focused descendant, lifecycle and toast order before publication. Only a close containing the actually focused Root can replace that origin; ownerless Viewport focus retains the outer ID. Every nested close-all remains sticky. Removed origins retain their original next/previous neighbor order, while fresh same-ID lifecycles take precedence. Explicit consumer blur cancels owned-focus recovery; silent exit/replacement DOM loss can recover focus at entry or after rendering. Viewport reads fresh state and its current owner document's active/focus-visible element; callbacks may move focus, add/replace toasts, replace registrations or dispose. After callbacks, Viewport synchronously flushes the published state before selecting refs for additions, index-keyed rebinding and newly un-limited successors, then rechecks the opaque live registration, connected viewport and fresh owner-document focus. A fresh non-ending same-ID replacement is selected before the next/previous scan. A successor closed/replaced by its own focus listener is committed and reselected within the same transaction before returning. Actual contained focus is reconciled after transfer, including a reused active Root whose focus call emits no event; its timers remain paused. No tick/effect approximation owns close focus. Disposal or a thrown onClose prevents focus work. The next-then-previous non-ending scan preserves upstream behavior, including its lack of a limited-entry filter on close. Two further explicit uncredited corrections preserve focus in a different live toast during a single-ID close and clear a stale focus pause after physical Root removal, including while other exits remain. The latter reconciles actual composed focus without moving it and keeps hover/window pause policy intact. A pre/post rendering witness preserves a still-live toast's same lifecycle focus when a delayed sibling exit destroys its index-keyed DOM slot; it requires an unchanged release witness, disconnected old focus, fresh connected ref, live ownership and BODY, so outside focus or explicit blur wins. Ending toast exits receive no focus transfer from this witness, which expires within the current rendering commit. Another explicit uncredited correction derives --toast-frontmost-height from the first non-ending measured Root throughout animated exits; pinned upstream reads the ending array head and shares the original defect.
