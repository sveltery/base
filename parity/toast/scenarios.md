## Minimal vertical slice

Implement one per-Provider manager/store, a context-bound reactive facade and external manager bridge; inline fixed-position Viewport; keyed Root and Content; Title/Description registration; basic native Action/Close; timers, hover/focus-visible/window blur and cleanup; low/high structural announcements; actual keyboard F6/Tab/Shift+Tab/Escape; ending presence and onRemove. Render basic text content and explicit snippet children. Exercise limit with four notifications so a third-slot-only demo cannot conceal inert/metadata behavior. This is a contained slice, **not complete Toast or a drop-in Sonner API**.

For the first fixture set pass `swipeDirection=[]` explicitly. That is an upstream-supported opt-out used to isolate basic rendering and timers. Default down/right swipe, pointer capture, gesture CSS, anchored Positioner/Arrow, broad portal/shadow/ref/render conformance and rich content remain unported gates. Do not ship default gesture parity claims until their cases execute. Adding inline rendering without relocating DOM lets core/basic accessibility proceed independently; a body portal and Dialog coexistence are a release gate for the intended application replacement.

## Dialog/isolation release gate

Current actual code: [isolation.ts](../../packages/base/src/lib/overlay/isolation.ts), [dialog-overlay.svelte.ts](../../packages/base/src/lib/overlay/dialog-overlay.svelte.ts), [nonmodal guards](../../packages/base/src/lib/dialog/Portal.svelte), and [documented modal limits](../dialog/modal-isolation.md). Pinned behavioral references: [markOthers.ts](https://github.com/mui/base-ui/blob/47b40521eab921c2756bf9bdb0b0f07fbfdb8c8c/packages/react/src/floating-ui-react/utils/markOthers.ts) and Toast Root/Viewport keyboard/ARIA code traced above.

`isolateDialog` snapshots popup/descendant portals and existing `[aria-live]` surfaces for aria-hidden claims. Its separate `data-base-ui-inert` marking has no live exemption and is not native inert. It does not observe newly introduced live surfaces. Modal/trap-focus Dialog also traps Tab with the Dialog document stack. Toast does not belong to that stack; its own limited state uses **native** inert. Global Toast F6 on owner window can move outside a modal Dialog, while subsequent Dialog Tab handling may reclaim focus. No complete cross-component guarantee follows from isolated component tests.

Proposed `ToastIsolationFixture.svelte` / paired React fixture matrix (all **unported**):

| Topology / ordered operations | Required exact observations |
| --- | --- |
| Pre-mounted empty inline viewport, open modal Dialog, then add low/high Toast | Inspect viewport/root/urgent alert and every ancestor to body: no unexpected inherited aria-hidden suppresses intended live output. Check Notifications region, polite surface, atomic alert text and high visible root hidden state. Dialog popup label/description and background isolation unchanged. Verify which nodes carry data-base-ui-inert separately from native inert. |
| Open modal first; create inline or body-portal viewport afterward; then add/update notification | Repeat ancestor checks and announcements, exposing snapshot/hidden-parent failure. A newly inserted viewport under an already-hidden app wrapper is a concrete likely failure, not evidence of a supported exemption. Compare real React before choosing shared fix. |
| Urgent alert sibling outside live viewport; Dialog opened before/after its mount | Current preservation selector is `[aria-live]`, not `[role=alert]`. Inspect urgent sibling's own aria-hidden plus inherited hidden ancestors independently; do not infer urgent exposure merely from the polite viewport. |
| Toast inside Dialog vs body sibling; F6→Tab→Shift+Tab→Escape; focus in Action/Close and portaled child | Record activeElement at each key, toast presence, Dialog open, close callbacks and original focus owner. Tab trapping/return and simultaneous Escape ownership must match actual reference under both topologies. No synthetic Event-only focus test certifies this. |
| Two overlapping/nested Dialogs; change modal true→trap-focus→false; add/close/remount Toast; close Dialogs in either order | Preserve per-document isolation claim counts, externally supplied aria-hidden/native inert and scroll-lock styles; keep required live output exposed for remaining owner. Toast closing must not alter Dialog stack/scroll lock or remove another owner's attributes. |
| Provider/viewport unmount while timers paused and Dialog remains open; then remount | Exact cleanup of Toast window/document subscriptions/observers/timers; no leftover guards or focus theft. Existing Dialog listeners and isolation retain their own claims. |

If this matrix needs shared isolation/focus changes, the parent coordinates a separate scoped patch with paired tests. This PR deliberately owns no shared overlay file. Modal integration remains a blocker for a complete Sonner replacement claim until these fixtures execute and any fixes are reviewed.
