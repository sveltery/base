# Native component acceptance successor

This maintained acceptance projection follows the explicit native rendering directive: each real component calls its three-argument snippet or renders its literal intrinsic fallback. Public host/input references use native element bindings. Authored attachments spread onto actual hosts and retain native Svelte lifetime. The current Source implementation is proposed in [PR #77](https://github.com/sveltery/base/pull/77).

The Original remains Base UI v1.8.0 at `47b40521eab921c2756bf9bdb0b0f07fbfdb8c8c`. Its assertions, source hashes, declaration denominators and historical receipts remain unchanged. [The exact predecessor archive](acceptance-history/manifest.json) preserves every retired renderer-specific body and each migrated active fixture/check before editing. Those bodies are historical evidence, not passing evidence for the changed API. The archive's predecessor is `0991faa82bf635b7ca7b2ab2193bd170ee7af468`; the manifest records immutable SHA-256 hashes and zero unchanged parity credit.

Native counterpart assertions are supplemental acceptance and earn **zero unchanged React renderer credit**. Domain assertions retained from existing feature suites retain their original scope; this migration does not mark historical failed, divergent, unported or unexecuted assertions as passing. The changed Collapsible replacement-host case explicitly expects native Svelte to open the current host while preserving the unchanged React reference observation in its own branch. The original full body is archived.

The live consistency check is `scripts/tests/native-snippets-provenance.test.mjs`. It validates the archive hashes, frozen Original rendering declaration/type scope, retired export exclusions and the current native Source import graph. It does not run obsolete historical graph checks against retired local files and does not reinterpret their frozen evidence.

Execution status at authoring: cached Svelte client/server syntax and TypeScript parser checks have been used without installing dependencies. No new full runtime, browser, installed-package or type execution receipt is claimed here. Final exact-head Standards, Verification, focused native browser execution and independent source/acceptance review remain required. Source import closure and parser success do not establish those outcomes.
