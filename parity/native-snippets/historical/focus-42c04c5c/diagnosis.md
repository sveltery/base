# Independent native focus-owner lifetime diagnosis

The source establishes one unintended lifetime input: the return-focus effect synchronously reads the live opening interaction type when it installs its owner. Closing Dialog resets that value while its popup remains mounted; reopening a retained Menu changes it again. Native Svelte consequently disposes and reinstalls this focus owner, and its disposal body returns focus or calls `finalFocus`. The opening method is captured metadata for default-return priority in the pinned source, rather than an input that invalidates the installed resource. This is a source-supported repair candidate. The six actual failures have not been rerun by this reviewer, and neither SOURCE CLEAR nor RUNTIME CLEAR is granted.

| --- | --- |
| `open` | Tracked in initial-focus, interaction, aria and portal-state effects. It is not read synchronously by return-focus setup. Actual open changes must continue canceling animation-completion watchers. |

Installed Svelte5.57.1 source provides the primitive evidence. `runtime.js:get` at548 enrolls a read when `active_reaction !== null && !untracking`. `update_effect` at455 invokes old teardown before `update_reaction`. `effects.js:execute_effect_teardown` at445 sets `active_reaction` to null before calling cleanup. `runtime.js:untrack` at784 suppresses the caller reaction's enrollment. The compiler's full `VariableDeclaration` body transforms destructured `$derived(getProps())` into individual property-derived reads; `deriveds.js`/`equality.js` filter unchanged values by native equality. Therefore a changed opening type is an effect dependency, rather than an incidental whole-props update. Cleanup reads retain Svelte's own destruction/old-value semantics (`runtime.js:659–683`); no custom committed-ref transport or forced snapshot is proposed.

The smallest source-supported candidate is to import native `untrack` and change only the captured metadata expression to `const preferPreviousFocus = untrack(() => openInteractionTypeRef.current == null);`, with a short explanation of the installed-owner metadata boundary. It preserves all source fallback ordering, false/undefined/null distinctions, close-type classification, prevention/cancellation guards, connected-element checks, tree membership, finalFocus callback selection, focus-visible handling and real disabled/node/subscription cleanup. It does not require a state factory, broad class conversion, effect tuple, Object.is guard, framework cache, boxed metadata record, blanket untrack, ref fan-out, renderer restoration or React commit simulation.
