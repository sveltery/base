# UseRender compatibility decision

Reference: Base UI v1.8.0 `47b40521eab921c2756bf9bdb0b0f07fbfdb8c8c`, [public useRender](https://github.com/mui/base-ui/blob/47b40521eab921c2756bf9bdb0b0f07fbfdb8c8c/packages/react/src/use-render/useRender.ts), [private rendering closure](https://github.com/mui/base-ui/blob/47b40521eab921c2756bf9bdb0b0f07fbfdb8c8c/packages/react/src/internals/useRenderElement.tsx), and [merged-ref lifecycle](https://github.com/mui/base-ui/blob/47b40521eab921c2756bf9bdb0b0f07fbfdb8c8c/packages/utils/src/useMergedRefs.ts). Derived code/assertions retain MIT attribution.

Upstream `useRender(params)` returns a ReactElement or null with conditional return types. Locally `<UseRender {...params}/>` renders Svelte markup, with a replacement snippet rather than a cloneable ReactElement. The component/name/return API change is a specific [delegated PM design decision](https://github.com/sveltery/base/pull/40#pullrequestreview-5396533264), recorded against `8b24a8860a448122477298427b1ab1925f0ca909` on October 2, 2026; it is not one of the five historical syntax substitutions and no explicit user acceptance is recorded. All seven return-type assertions remain divergent/unported and receive zero credit. Public props remains an ordinary object; array/getter sources and state-dependent class/style callbacks belong to the private source closure.

Native callback/object/array refs are fanned out separately from prop merge; callback cleanup supersedes null delivery, while callbacks with no cleanup receive null, matching the pinned merged-ref rule. Bindable actual-host `element` is a Svelte observation adaptation following A-01's initial undefined/host/null lifecycle. Replacement-owned refs use host attachments, and snippets merge their owned props after supplied props; neither a snippet nor its internals are cloned or introspected. Snippet-owned attachment lifecycle is separate from the supplied fanout; it cannot contribute its ref to React's single cloned-element merged-ref callback. Individual ref identity and empty slots determine memoization: the fixed form compares four positions and the array form also compares length, preserving the actual pinned comparator. Native pre-update cleanup releases a replaced supplied ref before host mutation, then an idempotent attachment releases it at most once and attaches the new refs to the actual updated host. Class-only updates preserve existing refs. Native string CSS preserves the authored cascade rather than accepting React CSS objects. Native events preserve independent native-default prevention and Base UI handler suppression through the existing mergeProps baseline.

React lazy/Suspense, Flight/RSC and invalid-render/function-name diagnostics remain unimplemented. Their twelve internal source sites/fifteen variants and the seven divergent type assertions are uncredited. DirectionProvider and CSPProvider are independent foundations, not dependencies of this source closure. This change does not migrate existing components or claim complete shared-helper/library parity.

An additional native teardown observation follows a separate [delegated PM lifecycle decision](https://github.com/sveltery/base/pull/40#pullrequestreview-5397289277), recorded against `8945685e9ec3ba92de61dee31e73f9f60e80801b`: on full owning-component unmount and host replacement controlled inside a snippet, Svelte removes the host before attachment cleanup, so callback cleanup observes `host.isConnected === false`; actual pinned React cleanup observes true. The callback receives the actual host with its authored attributes intact. The implementation does not reconnect it, fabricate observations or introspect snippets. Ref identity replacement, disabling, known default-tag swaps, default-host/snippet branch changes and supplied snippet identity changes use pre-update cleanup and retain connected-host observations. Direct actual React/Svelte probes and explicitly divergent supplemental browser characterizations record the two remaining paths; they earn zero unchanged credit. This specific delegated decision is separate from the earlier public API design review; explicit user acceptance and final implementation/merge approval are not recorded.

The [specific PM clarification 5397832880](https://github.com/sveltery/base/pull/40#pullrequestreview-5397832880), recorded against `81841bc7cf0891b0eee577c2c1b75bb534aea8ed`, classifies changed supplied snippet identity as a native host replacement, even with the same intrinsic tag. Actual React type/key reuse retains the same host and ref attachment in that case; Svelte replaces the host, pre-releases the connected old host, then attaches the new host. Stable supplied snippet identity with reactive props/state arguments retains its host and refs. This separate observable identity/ref difference receives zero unchanged credit and has no recorded explicit user acceptance; any affected ordinary assertion remains individually divergent or unimplemented. The earlier after-removal exception is limited to full owner unmount and host changes internal to an unchanged snippet. No final implementation or merge approval is implied.

Evidence: 61 focused actual Svelte DOM assertion ports/supplements, seven exact-source initialization/ownership/writability regressions, immutable source trace and isolated internal tarball SSR/native types pass locally. Eight direct actual React/Svelte host audits and the server ref-array getter probe also pass; they add no ordinary declaration credit. The two additional connection probes record the divergence above. The [verification history](verification.md) preserves failed source-review candidates even when their browser jobs passed. Secured paired successor execution and exact final-head/public package gates remain required before PM approval/merge. Proposed [PR #40](https://github.com/sveltery/base/pull/40) anchors the delegated PM public design review; immutable passing browser checkpoints will be recorded when available. Implementation approval is not merge approval or explicit acceptance of product differences.
